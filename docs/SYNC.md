# 동기화(선택): goyo-sync

<b>한국어</b> · [English](SYNC.en.md)

0.8.0부터 여러 PC에서 같은 금고를 쓸 수 있도록, **암호화된 금고 파일만** 내 SSH 서버와 주고받는 별도 도구 `goyo-sync.exe`가 있습니다. 설치하지 않으면 아무것도 바뀌지 않습니다. 금고 앱 `goyo-vault.exe`에는 지금도 네트워크 코드와 다른 프로그램을 실행하는 코드가 없습니다.

> [!WARNING]
> - **동기화를 켠 금고와 그 뒤의 백업은 0.8.0 이상에서만 열립니다.** 0.7.x 이하는 '인증 실패'로 거부합니다. 되돌리는 기능은 없습니다. 모든 PC를 먼저 0.8.0 이상으로 업데이트하세요.
> - 처음 나온 기능입니다. 자동 테스트와 AI 검토만 거쳤고 전문 보안 감사는 받지 않았습니다. 켜기 전에 **금고 백업과 열쇠 백업**을 해 두세요.

이 문서의 `my-server`, `<user>`, `<you>`는 예시입니다. 자기 서버의 ssh 별칭과 사용자 이름으로 바꿔 쓰세요.

## 무엇이 오가고, 무엇이 PC에 남나요

- **서버로 가는 것:** 암호화된 금고 파일(`GOYOVA02` 형식, 0.9.0에서 열쇠를 바꾼 금고는 `GOYOVA04` 형식) 전체.
- **PC 밖으로 나가지 않는 것:** 열쇠 파일(`.goyokey`), 비밀번호, OTP 비밀키, 평문. 열쇠 파일이 없으면 서버도 goyo-sync도 금고를 풀 수 없습니다. 보안 키 실험 빌드의 '열쇠 파일 동기화'를 켠 금고만 예외입니다([SECURITY_KEY.md](SECURITY_KEY.md)).
- **서버가 아는 것:** 금고 ID, 파일 크기, 내용이 바뀐 시각, 접속한 IP, 보관한 버전 수. 그리고 도우미가 로그인해 있는 동안 `interval`(기본 60초)마다 접속하므로, **각 PC가 언제 켜져 있는지**도 압니다. 간격을 늘리면 덜 자세해집니다.
- **OTP만 바뀐 경우는 올리지 않습니다.** OTP를 쓰는 금고는 열 때마다 OTP 기록이 바뀌지만, 그것만으로는 서버에 올리지 않습니다. 서버가 이 PC의 업로드를 받지 않는 동안에도, 올라가기를 기다리는 파일은 금고를 연다고 새로 만들지 않습니다. 그래서 서버는 보통 언제 금고를 열었는지 모릅니다. 예외가 하나 있습니다. 아직 올라가지 않은 변경이 있는데 서버에서 새 사본이 오면, 금고 앱은 그 사본을 합친 뒤(닫혀 있었다면 다음에 열 때) 변경을 다시 올립니다. 서버는 그 시각을 압니다.

|프로그램|하는 일|하지 않는 일|
|---|---|---|
|`goyo-vault.exe` (금고 앱)|복호화, 다른 PC의 변경 합치기, 확인 코드 계산|네트워크, 다른 프로그램 실행|
|`goyo-sync.exe` (도우미)|설정 창, 암호화된 사본을 Windows 내장 `ssh.exe`로 서버와 주고받기|복호화, 금고·열쇠 파일 열기. 자체 네트워크·암호 코드도 없습니다.|
|`goyo-sync-server.py` (서버)|받은 암호문을 금고마다 버전별로 보관(최근 200개)|복호화(키가 없습니다). 상주 프로그램이나 열린 포트도 없습니다.|

금고 앱과 도우미는 금고 옆 `<금고 파일 이름>.sync` 폴더(예: `vault.goyo.sync`)의 파일로만 주고받습니다. 도우미는 금고 파일을 열지 않습니다. 금고 파일에 다른 프로그램의 핸들이 하나라도 열려 있으면 Windows가 금고 저장을 거부하기 때문입니다.

## 준비물

- 모든 PC에 고요 금고 **0.8.0 이상**.
- 각 PC에 Windows OpenSSH 클라이언트(`C:\Windows\System32\OpenSSH\ssh.exe`). Windows 11에는 보통 들어 있습니다. 없으면 **설정 > 시스템 > 선택적 기능**에서 'OpenSSH 클라이언트'를 추가하세요.
- `python3`(3.8 이상)와 `sshd`가 있는 서버 한 대. Linux를 기준으로 합니다. 내 계정으로 ssh 키 로그인이 되어야 합니다.
- 암호(passphrase) 없는 ssh 키나 ssh-agent 서비스. 도우미는 사람 없이 돌기 때문에 암호를 물을 수 없습니다.
- 서버의 호스트 키 지문을 확인할 방법(서버 콘솔이나 관리 화면). 처음 연결할 때 비교합니다.
- 집 밖에서도 쓰려면 ssh 포트를 인터넷에 열지 마세요. Tailscale 같은 VPN으로 서버에 닿게 하는 것을 권장합니다.

**0.9.0으로 업데이트하는 순서.** 0.9.0에서 열쇠(데이터 키)를 바꾼 금고는 `GOYOVA04` 형식으로 올라갑니다. 0.9.0의 서버 스크립트와 도우미는 `GOYOVA02`와 `GOYOVA04`를 모두 받지만, 그보다 오래된 것은 `GOYOVA04`를 받지 않습니다. 그러니 **서버 스크립트를 먼저**('서버에 설치·업데이트'), **그다음 모든 PC의 고요 금고와 goyo-sync를** 업데이트하고, 열쇠는 그 뒤에 바꾸세요. 순서가 어긋나면 이렇게 보입니다.

- 서버 스크립트가 오래됨: 0.9.0 도우미가 `oldserver` 상태('서버 스크립트 업데이트 필요')를 보이고, 금고 앱은 "서버의 goyo-sync 스크립트가 이 금고 형식을 받지 않습니다…"라고 알립니다. 변경은 이 PC에 남아 있고, 스크립트를 업데이트하면 10분 안에(또는 도우미를 다시 시작하면 바로) 올라갑니다.
- 도우미가 0.8: 올릴 파일을 도우미 자신의 검사가 거부해 `refused`(동기화 경고, "동기화 오류: goyo-sync.log를 확인하세요")만 보입니다. 로그에는 `refused outgoing before upload`가 남습니다. goyo-sync를 0.9.0으로 바꾸면 처음 실행할 때 그 파일을 한 번 다시 올립니다.
- 고요 금고가 0.8: `GOYOVA03`/`GOYOVA04` 금고 파일과 서버 사본을 "더 새로운 버전에서 만든 금고 형식입니다"로 거부하고 동기화를 멈춥니다. 덮어쓰지는 않습니다.

## 1. 설치하고 설정 창 열기

`goyo-sync.exe`, `server\goyo-sync-server.py`, `goyo-sync.conf.example`은 README의 '설치'대로 만든 고요 금고 ZIP의 `GoyoVault` 폴더에 함께 들어 있습니다. 따로 설치할 것은 없습니다.

GoyoVault 폴더에서 **`goyo-sync.exe`를 더블클릭**하면 설정 창이 열립니다. 고요 금고와 같은 모양이고, 다크·라이트와 한국어·English는 금고 앱에서 고른 대로 따라갑니다. 창은 하나만 열리며, 다시 실행하면 열려 있는 창이 앞으로 옵니다.

창은 위에서부터 세 부분입니다.

- **서버**: ssh 호스트, '연결 확인', '서버에 설치·업데이트', 결과 줄, '고급 설정'.
- **금고**: 동기화할 금고 목록과 각 금고의 상태, '추가…', '빼기', '이 PC로 가져오기…'(다른 PC의 금고를 서버에서 가져옴). 보안 키 빌드는 목록 아래에 '강제 명령 줄…'이 있습니다.
- **실행**: 'Windows에 로그인하면 자동으로 시작', '저장하고 시작', '지금 동기화', '중지', '로그 보기', 상태 줄.

제목 옆 표시는 백그라운드 동기화가 실행 중인지 보여 줍니다. 창을 닫아도 백그라운드 동기화는 계속됩니다.

## 2. 서버 연결

1. **서버 (ssh 호스트)** 칸에 `%USERPROFILE%\.ssh\config`의 별칭(예: `my-server`)이나 `<user>@my-server`를 적습니다. 포트 같은 설정은 ssh config의 별칭에 적으세요.
2. **서버에 설치·업데이트**를 누릅니다. 확인 창에 서버와 설치 위치가 나옵니다. '예'를 누르면 goyo-sync.exe에 들어 있는 서버 스크립트를 ssh 표준 입력으로 보내고, 서버에서 다음 한 줄만 실행합니다(경로는 고급 설정 값).
   ```
   umask 077 && mkdir -p .local/share/goyo-sync && cat > .local/share/goyo-sync/goyo-sync-server.py.new && chmod 700 .local/share/goyo-sync/goyo-sync-server.py.new && python3 -I .local/share/goyo-sync/goyo-sync-server.py.new selftest && mv -f .local/share/goyo-sync/goyo-sync-server.py.new .local/share/goyo-sync/goyo-sync-server.py
   ```
   받은 사본(`.new`)의 selftest가 통과해야만 기존 스크립트와 바꾸므로, 전송이 중간에 끊겨도 잘린 스크립트가 설치되지 않습니다. selftest가 정확히 `PASS`만 출력하고 바꾸기까지 끝나야 설치된 것으로 봅니다. 그 서버에서 저장, 동시 저장 충돌(실제 스레드 경쟁 포함), 기록 200개 유지, 열쇠 파일 거부, 폴더 fsync, 파일이나 링크인 저장소 거부, 동시에 처음 올릴 때의 금고 64개 한도, 동시 접속 8개 제한(실제 serve 프로세스 포함), 디스크 여유 공간 기준(256 MiB)을 직접 시험한 결과입니다. 개발 중 Ubuntu(Python 3.12)에서도 통과했지만(POSIX에서만 도는 금고 수 잠금·동시 접속 제한·여유 공간 시험 포함), 서버마다 파일 시스템과 python이 다르니 설치할 때 한 번은 꼭 실행됩니다. 서버를 옮기거나 python을 바꿨을 때, goyo-sync를 업데이트했을 때도 다시 누르세요. 시간 제한(헤더 30초, 업로드 600초, 응답 60초·600초)은 거는 순서만 시험하고, 실제로 시간이 지나 끊기는지는 시험하지 않습니다.
   - 설치에는 **평소의 ssh 로그인**(기본 키나 ssh-agent)을 씁니다. 아래 '전용 키'는 서버에서 동기화 명령만 실행하도록 묶여 있을 수 있어 쓰지 않습니다.
   - 처음 연결하는 서버라면 먼저 3번의 '연결 확인'으로 호스트 키를 받아 두세요. 설치는 모르는 호스트 키로 연결하지 않습니다.
   - 서버 스크립트는 ssh 접속 한 번에 요청 하나를 처리하고 끝납니다. 데이터는 스크립트 폴더의 `data` 아래(기본 `~/.local/share/goyo-sync/data/`)에 금고마다 버전 파일로 남습니다(폴더 0700, 파일 0600). 같은 폴더에 동시 접속을 세는 빈 잠금 파일 `slot-0`~`slot-7`도 생깁니다(POSIX). 저장 공간은 최대 금고 64개 × 버전 200개 × 8 MiB, 약 100 GiB이지만, 저장한 뒤 디스크 여유 공간이 256 MiB보다 적어지는 업로드는 거부합니다. 서버의 다른 용도와 공간을 나누려면 `data` 폴더를 별도 파일 시스템이나 할당량 아래에 두세요.
3. **연결 확인**을 누릅니다. 설정을 goyo-sync.conf와 똑같은 규칙으로 검사하고(틀린 칸은 빨간 테두리), 백그라운드 도우미와 같은 ssh 옵션으로 512바이트 이진 데이터 왕복과 서버의 금고 목록을 확인합니다. 아무것도 쓰지 않습니다. 결과 줄이 `연결 정상 · … 서버에 금고 N개`이면 됩니다. 실패하면 원인(오프라인, 인증, 호스트 키, ssh.exe 없음, 서버 스크립트 없음, 파이썬 없음, 서버 오류)이 결과 줄에 나옵니다.

ssh 작업은 모두 창 뒤에서 돌고, 그동안 진행 시간이 결과 줄에 나옵니다. 한 번의 ssh 호출은 고급 설정의 제한 시간(기본 120초)을 넘지 않습니다.

### 처음 연결: 호스트 키

goyo-sync의 ssh는 모르는 호스트 키나 바뀐 호스트 키로는 연결하지 않습니다(`StrictHostKeyChecking=yes`). 이 PC의 `known_hosts`에 아직 없는 서버면 '연결 확인'이 묻습니다.

- **예**: 이번 한 번만 `StrictHostKeyChecking=accept-new`로 접속해, 서버가 보낸 키를 확인 없이 `known_hosts`에 저장합니다(처음 사용할 때 신뢰). 그 순간 누가 연결을 가로채고 있었다면 그 사람의 키가 저장되므로, 저장한 뒤 창이 **지문**(`ssh-keygen -l -F`의 출력, 예: `my-server ED25519 SHA256:…`)을 보여 줍니다. 서버에서 직접 확인한 지문(예: 서버에서 `ssh-keygen -l -f /etc/ssh/ssh_host_ed25519_key.pub`)과 꼭 비교하세요. 다르면 `ssh-keygen -R my-server`로 지우고 그 서버를 쓰지 마세요.
- **아니요**: 아무것도 저장하지 않습니다.
- 이름에 이미 **다른 키가 저장되어 있거나 키가 바뀌었다면** 묻지 않고 멈춥니다. 서버를 다시 설치했다는 확신이 있을 때만 서버에서 지문을 확인하고, PowerShell에서 `ssh-keygen -R my-server`로 예전 키를 지운 뒤 `ssh my-server`로 직접 접속해 비교하세요. 이 창은 바뀐 키를 받아들이지 않습니다.

PowerShell에서 `ssh my-server`로 직접 접속해 지문을 확인하고 받아 두어도 됩니다. 그러면 '연결 확인'은 묻지 않습니다.

### 고급 설정

'고급 설정' 스위치를 켜면 나머지 설정이 보입니다. 비워 둘 수 없는 칸은 기본값으로 채워져 있습니다.

|칸|기본값|뜻|
|---|---|---|
|서버의 스크립트 경로|`.local/share/goyo-sync/goyo-sync-server.py`|서버 홈 폴더 기준(`/`로 시작하면 절대 경로). 영문·숫자·`. _ / ~ + -`|
|파이썬 명령|`python3`|서버의 파이썬 명령. 영문·숫자·`. _ / + -`|
|간격(초)|`60`|서버의 새 버전을 확인하는 간격, 30~3600. PC끼리 겹치지 않게 ±10% 흔들립니다.|
|제한(초)|`120`|ssh 호출 한 번의 제한 시간, 30~600. 느린 회선으로 큰 금고를 올린다면 늘리세요.|
|전용 SSH 키 파일|(비움)|전용 ssh 개인 키. '찾기'로 고릅니다. 적으면 그 키만 씁니다. `.goyokey`·`.goyo` 파일은 거부합니다.|

**열쇠 파일을 지정하는 설정은 없습니다.** 쓰는 ssh도 바꿀 수 없고, 항상 `System32\OpenSSH\ssh.exe`를 정해진 옵션으로 실행합니다(모르는 호스트 키 거부, 포워딩·터미널 없음, 비밀번호 질문 없음).

### 전용 키와 강제 명령 (권장)

goyo-sync 전용 ssh 키를 만들고, 서버에서 그 키로는 동기화 스크립트만 실행되게 묶습니다. 이 키를 도난당해도 암호문 저장소에만 닿고 서버 셸은 열리지 않습니다. 강제 명령도 셸을 거쳐 실행되므로, 셸 시작 파일(`~/.bashrc`, `~/.zshenv` 등)이 출력하는 글은 그대로 섞입니다. 그런 출력은 아래 문제 해결의 `banner=N`을 보세요.

1. 먼저 '서버에 설치·업데이트'로 스크립트를 설치합니다(평소 로그인을 씁니다).
2. PC에서 키를 만듭니다. 암호는 비우거나 ssh-agent 서비스를 쓰세요.
   ```powershell
   ssh-keygen -t ed25519 -f $HOME\.ssh\goyo_sync -C goyo-sync
   ```
3. 서버의 `~/.ssh/authorized_keys`에 공개 키(`goyo_sync.pub`의 내용)를 이렇게 한 줄로 넣습니다. python 경로는 서버에서 `command -v python3`로 확인하세요.
   ```
   restrict,command="/usr/bin/python3 -I /home/<user>/.local/share/goyo-sync/goyo-sync-server.py serve" ssh-ed25519 AAAA… goyo-sync
   ```
4. 고급 설정의 **전용 SSH 키 파일**에 `C:\Users\<you>\.ssh\goyo_sync`를 고르고 '연결 확인'을 누릅니다.

**키 파일은 내 Windows 계정만 읽을 수 있어야 합니다.** 위처럼 `ssh-keygen`으로 만든 키는 그렇지만, 다른 폴더나 다른 PC에서 복사해 온 키는 그 폴더의 권한을 물려받아 다른 계정(Users 등)도 읽을 수 있게 될 수 있습니다. 그러면 Windows의 ssh는 그 키를 조용히 무시하고(`-E` 로그에 `UNPROTECTED PRIVATE KEY FILE`, `bad permissions`) 평소 키로 접속합니다. 평소 키에는 강제 명령이 없으므로 서버는 `--key-sync`가 없는 연결로 봅니다. goyo-sync는 전용 키를 정했는데 ssh가 그 키를 무시한 연결은 쓰지 않습니다: 도우미는 `auth`가 되고 로그에 `the dedicated SSH key was ignored: bad permissions`를 남기며, '연결 확인'은 그 이유와 고치는 명령을 보여 줍니다. 판단은 ssh 로그가 **전용 키 파일 이름** 을 들어 경고할 때만 합니다(`~/.ssh/config`의 다른 키 파일에 대한 같은 경고는 전용 키가 쓰였으므로 상관없습니다). PowerShell에서 이렇게 고칩니다.
```powershell
icacls "$HOME\.ssh\goyo_sync" /inheritance:r
icacls "$HOME\.ssh\goyo_sync" /grant:r "$($env:USERNAME):F"
```
설정 창은 키를 만들지 않습니다. 키는 언제나 위의 `ssh-keygen`으로 이 PC에서 만드세요.

PC가 여러 대면 PC마다 키를 따로 만들어 각각 한 줄씩 넣으세요. PC 한 대를 잃었을 때 그 줄만 지우면 됩니다. 보안 키 빌드의 열쇠 파일 동기화를 쓰는 금고는 이 줄에 `--key-sync=<금고 ID>`를 더 붙입니다. 보안 키 빌드의 설정 창에서 '강제 명령 줄…'을 누르면 목록의 금고 가운데 열쇠 파일 동기화를 쓰는 금고를 넣은 줄을 만들어 줍니다(아래 '열쇠 파일 동기화'). 나중에 스크립트를 업데이트할 때도 '서버에 설치·업데이트'는 평소 로그인을 쓰므로 전용 키와 상관없이 됩니다.

## 3. 금고 고르고 시작하기

1. **금고** 목록에 동기화할 금고 파일을 넣습니다. 목록이 비어 있고 GoyoVault 폴더에 `vault.goyo`가 있으면 처음부터 들어 있습니다. 다른 금고는 **추가…**로 고르세요(최대 8개). 열쇠 파일(`*.goyokey`)은 거부합니다. **빼기**는 고른 금고를 목록에서만 뺍니다.
2. **Windows에 로그인하면 자동으로 시작**을 확인합니다. 처음 설정할 때는 켜져 있습니다. 끄면 바로 꺼지고(현재 사용자 레지스트리의 Run 값 `GoyoSync`를 지움), 켜기는 '저장하고 시작'을 누를 때 적용됩니다.
3. **저장하고 시작**을 누릅니다. 설정을 검사한 뒤 실행 파일 옆 `goyo-sync.conf`에 저장하고(짧은 설명이 붙은 텍스트, 손으로 고쳐도 됩니다), 자동 시작을 적용하고, 실행 중인 도우미가 있으면 멈춘 뒤 `goyo-sync.exe --background`를 창 없이 새로 시작합니다. 제목 옆 표시가 '백그라운드 동기화 실행 중'으로 바뀝니다.
4. 도우미가 금고 옆에 `vault.goyo.sync` 폴더를 만들고, 목록의 상태가 '고요 금고에서 동기화 동의를 기다리는 중'이 됩니다. 이제 고요 금고로 그 금고를 엽니다(아래 '4. 동기화 켜기').

목록의 상태는 2초마다 동기화 폴더의 `status`·`helper.state` 파일에서 새로 읽습니다.

|상태|뜻|
|---|---|
|아직 설정 전|동기화 폴더가 없습니다. 저장하고 시작하면 도우미가 만듭니다.|
|고요 금고에서 동기화 동의를 기다리는 중|금고 앱이 아직 사본을 남기지 않았습니다. 금고를 열면 동의를 묻습니다.|
|정상 · 서버 버전 N|도우미가 서버와 주고받고 있고, 받은 사본이 서버 버전 N입니다.|
|도우미 꺼짐|3분 넘게 도우미의 상태 기록이 없습니다.|
|오프라인 / SSH 인증 실패 / 호스트 키 확인 필요 / 서버 오류 / 업로드 거부됨 / 설정 오류 / 새 형식|아래 '10. 문제 해결'의 같은 상태를 보세요.|
|금고 파일을 찾을 수 없습니다|경로를 확인하세요. 금고 파일은 폴더 목록으로만 확인하고 열지 않습니다.|
|… · 열쇠: 서버에 있음 / 서버에 없음 / 서버가 허용 안 함|(보안 키 빌드) 도우미가 마지막으로 본, 서버가 가진 이 금고의 열쇠 파일입니다. '서버가 허용 안 함'은 이 PC의 강제 명령 줄에 그 금고의 `--key-sync`가 없다는 뜻이며, 열쇠 파일 동기화를 쓰는 금고에만 나옵니다(열쇠 파일을 PC에만 두는 금고는 아무 표시도 하지 않습니다). 그런 금고의 상태가 '열쇠: 서버가 허용 안 함 · '강제 명령 줄…'의 줄로 바꾸세요'(`nokeys`)이면 줄을 바꾸세요.|

- **지금 동기화**: 목록의 모든 금고를 지금 한 번 동기화하고 금고마다 결과를 목록에 1분 동안 보여 줍니다(`--once`와 같음). 백그라운드 도우미가 그 금고를 처리하는 중이면 건너뜁니다.
- **중지**: 실행 중인 백그라운드 도우미를 멈춥니다(`--stop`과 같음).
- **로그 보기**: `goyo-sync.log`의 최근 400줄을 창 안에서 보여 줍니다(256 KiB가 넘어 넘어간 `goyo-sync.log.1`도 이어서).

저장하지 않은 변경이 있으면 상태 줄이 알려 주고, 창을 닫을 때 한 번 묻습니다.

## 4. 동기화 켜기

동기화 폴더가 생긴 뒤 고요 금고로 그 금고를 열면 확인 창이 나옵니다. 열쇠 파일과 비밀번호는 보내지 않는다는 것, 금고 형식이 바뀌어 **0.7 이하에서는 이 금고와 이후 백업을 열 수 없다는 것**을 알립니다. 0.9.0에서 열쇠를 바꾼 금고라면 대신 **0.8 이하에서는 열 수 없고 0.8 서버 스크립트는 사본을 받지 않으니, 서버 스크립트를 먼저, 그다음 다른 PC를 0.9.0 이상으로 업데이트하라고** 알립니다(위 '0.9.0으로 업데이트하는 순서').

- **예:** 금고가 동기화 형식(`GOYOVA02`)으로 바뀌고 첫 사본이 서버로 올라갑니다. 금고 화면 위에 '동기화됨'이 나오면 서버가 받았다고 답한 것입니다.
- **아니요:** 아무것도 바뀌지 않습니다. 다음에 열 때 다시 묻습니다. 그만 묻게 하려면 설정 창에서 그 금고를 **빼기**한 뒤 **저장하고 시작**을 누르고, `vault.goyo.sync` 폴더를 지우세요.
- 열쇠 파일이 동기화 폴더 안에 있으면 묻지 않고 경고합니다. 열쇠는 다른 곳으로 옮기세요.

금고 내용은 그대로이고, 확인 창은 금고를 열 때(잠금 해제)만 나옵니다. 백업 파일로 되살리거나 새로 만든 금고에는 나오지 않습니다.

**동기화는 금고 하나를 한 PC에서 먼저 켜세요.** 다른 PC에 예전부터 갖고 있던 사본이나 따로 고친 사본이 있다면, 그 사본에서 동기화를 켜지 말고 '6. 두 번째 PC 추가'처럼 서버 사본(또는 첫 PC의 금고)으로 복원해 바꾸세요. 동기화 전 형식에는 삭제 기록이 없어서, 한쪽에서 지우거나 고친 항목이 다른 쪽 사본에서 예전 내용 그대로 다시 합쳐집니다.

## 5. 화면 표시와 알림

금고를 열면 위쪽 표시가 `열림 · 동기화됨 · vault.goyo`처럼 바뀝니다.

|표시|뜻|
|---|---|
|**동기화됨**|이 PC의 항목과 삭제 기록이, 서버가 마지막으로 보내 왔거나 받았다고 답한 사본과 같다는 것을 **열쇠로 직접 확인**했습니다. 도우미의 상태 단어로는 나오지 않습니다. 서버가 받았다고 답하면 도우미는 이 PC가 올린 파일을 그대로 받은 사본으로 두므로, 서버가 실제로 저장했다는 증명은 아닙니다. 서버 디스크가 안전하다는 보증도 아닙니다.|
|**올리는 중**|바뀐 내용이 도우미나 서버를 기다리고 있습니다. 변경은 이 PC에 이미 저장되어 있습니다.|
|**도우미 꺼짐**|`goyo-sync.exe`가 실행 중이 아닙니다(상태 파일이 없거나 3분 넘게 갱신되지 않음).|
|**연결 안 됨**|도우미가 서버에 닿지 못합니다. 아래 문제 해결의 `offline`·`auth`·`hostkey`·`nossh`·`server`.|
|**동기화 경고**|확인이 필요합니다. 서버가 예전 상태를 보냈거나, 받은 사본이 인증에 실패했거나, 합치면 한도를 넘거나, 더 새로운 형식이거나, 도우미가 `refused`·`config`·`update`·`oldserver`·`keyfile` 상태입니다. 금고 쪽 경고는 잠글 때까지 유지됩니다. 다른 PC가 열쇠를 바꾼 서버 사본 때문에 멈췄거나 이 PC가 예전 열쇠 파일로 열려 있는 동안에도 이 표시입니다(아래 '열쇠를 바꾼 뒤').|

**확인 코드.** 금고를 열 때(또는 그 뒤 처음 동기화되었을 때) 상태 줄에 `동기화됨 · 확인 코드 XXXX-XXXX-XXXX-XXXX`가 한 번 나옵니다. 살아 있는 항목마다 ID와 내용(네 칸 모두)을, 그리고 삭제 기록을 넣어 계산하므로 **두 PC의 코드가 같으면 같은 내용**입니다. 0.9.0 열쇠 파일(열쇠를 바꾼 금고)로 연 금고는 열쇠 파일의 상태(수정 번호와 태그)도 넣으므로, 두 PC가 같은 열쇠 파일을 가졌을 때만 같은 코드가 됩니다. 다르면 아직 동기화 중이거나, 한 PC가 새 열쇠 파일을 아직 받지 않았거나, 서버가 PC마다 다른 사본을 보여 주고 있는 것입니다. ID 키(처음 데이터 키)로 계산하므로 코드로 항목 내용을 알 수는 없습니다. 64비트라서, 열쇠를 가진 사람도 다른 내용을 같은 코드로 맞추려면 약 2^64번 계산해야 합니다. OTP 기록은 넣지 않습니다. 다시 보려면 잠갔다가 여세요. 열쇠 파일끼리 비교하는 '열쇠 확인 코드'는 '열쇠 관리'에 있습니다.

상태 줄 알림:

|알림|뜻과 할 일|
|---|---|
|다른 PC의 변경을 합쳤습니다: 추가 N개, 삭제 N개.|정상입니다.|
|두 PC에서 함께 고친 항목 N개는 두 버전을 모두 남겼습니다. 이름이 같은 항목을 확인하세요.|같은 이름의 항목을 찾아 필요 없는 쪽을 지우세요. 알림은 항목 이름을 쓰지 않습니다. 상태 줄은 다른 프로그램이 읽을 수 있는 창 글자이기 때문입니다.|
|다른 PC에서 항목 N개가 삭제되거나 수정되었습니다. 합치기 전 상태를 …에 보관했습니다.|빨간 글씨로 나옵니다. N은 이번에 금고를 연 뒤 합치기로 사라진 항목 수입니다(그 사이 사본을 만들었다면 그 뒤로. '7. 함께 고치거나 지웠을 때'). 의도한 일이 아니면 아래 '되돌리기'를 보세요. 예전 열쇠 사본을 가진 누군가가 서버를 통해 지우거나 바꾼 것일 수도 있습니다.|
|경고: 서버가 이전 상태의 금고를 보냈습니다.|이 PC의 항목은 그대로이고, 이 PC의 상태를 다시 올립니다. 서버가 복원되었거나 누가 되돌렸을 수 있습니다. 다른 PC와 확인 코드를 비교하세요.|
|서버에서 받은 금고를 인증하지 못해 무시했습니다.|서버 사본이 손상되었거나 바뀌었습니다. 이 PC의 상태를 다시 올려 덮습니다.|
|서버 사본이 다른 금고의 것이라 무시했습니다.|같은 경로에 새 금고를 만들었거나 다른 금고를 복원한 경우입니다. 설정 창에서 '중지'를 누르고 `vault.goyo.sync` 폴더를 지운 뒤 '저장하고 시작'을 누르세요. 서버의 예전 금고 기록은 그대로 남습니다.|

## 6. 두 번째 PC 추가

1. 새 PC에 고요 금고 0.8.0 이상을 설치하고, 위 '준비물'처럼 서버에 ssh로 접속되게 합니다(키나 ssh-agent).
2. **열쇠 파일(`.goyokey`)을 USB로 옮깁니다.** 서버, 메일, 클라우드로 보내지 마세요.
3. `goyo-sync.exe`를 실행하고 서버를 적은 뒤 **연결 확인**을 누릅니다(처음 연결이면 지문을 비교하세요).
4. 금고 파일을 가져옵니다. 둘 중 하나를 고르세요.
   - **서버에서 가져오기:** **이 PC로 가져오기…**를 누르면 서버의 금고 목록이 나옵니다. 태그(예: `3FA2-C1D0`)는 OTP 앱에 등록된 이름 `Goyo Vault (3FA2-C1D0)`의 태그와 같습니다. 첫 PC에서 이 목록을 열면 그 금고에 '이 PC의 vault.goyo와 같은 금고'라고 나오므로 거기서도 태그를 확인할 수 있습니다. 보안 키 빌드는 금고마다 '열쇠 파일: 서버에 있음 / 서버에 없음 (USB로) / 이 PC 줄로는 확인 안 함'도 보여 줍니다(앞의 4개 금고까지만 묻습니다. 금고마다 ssh 접속이 한 번 더 들기 때문입니다). 새 PC는 아직 목록에 열쇠 파일 동기화 금고가 없어 '이 PC 줄로는 확인 안 함'이 나옵니다. 먼저 금고를 가져온 뒤 '강제 명령 줄…'을 누르면 그 금고가 줄에 들어갑니다. 금고를 고르고 **가져오기…**를 누른 뒤 저장할 **폴더**를 고릅니다. 이름은 `vault.goyo`가 기본이고(그 폴더가 고요 금고의 폴더면 고요 금고가 바로 엽니다), 같은 이름의 파일이나 동기화 폴더(`vault.goyo.sync`)가 이미 있으면 덮어쓰지 않고 다른 폴더를 고르라고 합니다. 서버의 최신 버전을 그 파일로 저장하고 **동기화 목록에 넣습니다**(저장하지 않은 변경). 끝나면 다음에 할 일을 창으로 알려 줍니다.
   - **USB로 옮기기:** 첫 PC의 `vault.goyo`도 USB로 옮겨 이 PC의 폴더에 넣고 **추가…**로 목록에 넣습니다. 서버를 믿을 필요가 없습니다.
5. 열쇠 파일을 그 금고 옆에 같은 이름(`vault.goyokey`)으로 넣습니다(2번). 보안 키 빌드에서 그 금고가 열쇠 파일 동기화를 쓰면 '이 PC로 가져오기'가 서버의 열쇠 파일도 동기화 폴더에 함께 가져오므로 USB가 필요 없고, 고요 금고가 **서버에서 가져온 금고** 화면에서 비밀번호, 보안 키, 다른 PC의 열쇠 확인 코드를 차례로 묻고 열쇠 파일을 금고 옆에 저장합니다([SECURITY_KEY.md](SECURITY_KEY.md)의 '새 PC').
6. **저장하고 시작**을 누르고 고요 금고로 그 금고를 엽니다(고요 금고 폴더의 `vault.goyo`가 아니면 **금고 파일 열기 (다른 폴더 · 서버에서 가져온 금고)**(또는 로그인 화면의 **찾기**)로 고릅니다). 이미 동기화 형식이라 확인 창 없이 연결됩니다. 처음 받는 사본은 서버를 믿고 받는 것이므로 연 뒤 아래쪽 상태 줄의 **'동기화됨 · 확인 코드 …'를 첫 PC의 것과 비교하세요.** 같으면 끝입니다(보안 키 빌드의 '열쇠 확인 코드'와는 다른 코드입니다).

**백업 파일로 되살리기**는 '금고 백업'으로 만든 백업 파일을 되살릴 때 씁니다. 다른 PC의 금고를 이 PC로 가져올 때는 쓰지 않습니다.

## 7. 함께 고치거나 지웠을 때

- 다른 PC의 변경은 도우미가 간격(기본 60초)마다 받아 오고, 금고 앱은 금고 화면과 '열쇠 관리' 화면에서 2초 안에 합칩니다. 항목을 편집하거나 대화 상자가 열려 있거나 열쇠 작업이 진행 중인 동안에는 기다렸다가 끝난 뒤 합칩니다. 앱이 닫혀 있으면 다음에 열 때, OTP를 확인하기 전에 합칩니다.
- 이 PC의 변경은 금고 파일에 먼저 저장된 뒤 올라갑니다. 서버가 이 PC에 없는 내용을 갖게 되는 일은 없습니다.
- **두 PC에서 같은 항목을 고치면 두 버전을 모두 남기고** 알립니다. 필요 없는 쪽을 지우세요. 그 삭제도 동기화됩니다.
- 한 PC에서 고치고 다른 PC에서 지우면 고친 쪽이 남습니다. 둘 다 지우면 사라집니다.
- 같은 내용을 두 PC에서 따로 추가하면 항목이 두 개가 됩니다. 하나를 지우세요.
- **삭제는 다른 PC에도 퍼집니다.** 동기화가 원래 하는 일입니다. 실수로 지웠다면 '되돌리기'를 보세요.
- 합치기로 이 PC의 항목이 많이 사라지면, 먼저 합치기 전 상태를 `vault.goyo.sync\pre-merge-<시각>.goyo`에 암호화된 사본으로 보관하고 빨간 글씨로 알립니다. 사라진 항목은 금고를 연 동안(잠금 해제부터 잠글 때까지)의 합치기마다 더해 셉니다. 마지막 사본 뒤로 5개 이상, 또는 2개 이상이면서 그 합치기 전 항목 수의 20% 이상이 되면 사본을 만들고, 사본에는 그 손실들 가운데 첫 번째 전의 상태가 들어갑니다. 다른 PC에서 지운 항목, 다른 PC에서 고친 항목(이 PC의 고치기 전 내용이 사라짐), 같은 ID에 들어온 다른 글에 밀려난 항목(다른 ID로 옮겨 남았더라도)이 모두 들어갑니다.
- 합치기 전 사본은 최근 3개가 오래되었어도 남고, 그 밖에는 30일이 안 된 것만 남습니다. 모두 합쳐 최근 20개까지입니다. 남지 않는 사본은 새 사본을 만들 때 지웁니다.
- 이 PC의 변경이 올라가기 전에 금고 앱을 닫았고 그사이 다른 PC가 먼저 올렸다면, 이 PC의 변경은 다음에 금고를 열 때 합친 뒤 올라갑니다. 합치려면 열쇠가 필요하기 때문입니다. 변경은 금고 파일에 있으니 잃는 것은 없습니다.
- 동기화 중에는 `vault.goyo`를 손으로 바꿔 넣지 마세요. 다른 사본을 쓰려면 **백업 파일로 되살리기**를 쓰세요. `vault.goyo.sync` 안의 파일도 고치지 마세요.

## 열쇠를 바꾼 뒤 (0.9.0)

0.9.0부터 비밀번호를 바꾸면 금고의 데이터 키가 바뀝니다(README의 '7. 열쇠 관리'). 동기화하는 금고에서는 이렇게 하세요.

- **업데이트 순서:** 서버 스크립트('서버에 설치·업데이트') → 모든 PC의 고요 금고와 goyo-sync → 그다음 열쇠 변경.
- **한 번에 한 PC에서만** 열쇠를 바꾸세요.
- **다른 PC에서는** 바꾼 PC의 새 열쇠 파일을 USB로 가져와 '열쇠 관리 › 새 열쇠 파일 받기'로 받습니다. 그 PC의 열쇠 파일 위에 **덮어쓰지 마세요.** 받을 때까지 그 PC는 "다른 PC에서 이 금고의 열쇠를 바꿔 동기화를 멈췄습니다…"로 멈추고, 그동안의 변경은 그 PC에만 저장되었다가 받은 뒤 합쳐집니다. 두 PC의 '열쇠 관리'에 보이는 열쇠 확인 코드(`E3 · …`)가 같으면 같은 열쇠 파일입니다.
- **금고 파일 하나를 여러 PC가 함께 쓰고(USB, 공유 폴더) 열쇠 파일은 PC마다 따로 둔 경우:** 한 PC에서 비밀번호를 바꾸면 다른 PC의 열쇠 파일로는 그 금고 파일이 더 열리지 않습니다("이 금고 파일은 다른 PC에서 바꾼 새 열쇠 파일(수정 N)로 저장되어 있어…"). 새 열쇠 파일을 그 PC들로 옮겨 그 파일로 여세요. 이때는 바꾼 직후의 열쇠 백업이 유일한 대비책입니다. 그 새 열쇠 파일을 잃으면 모든 PC에서 금고를 잃습니다.
- **금고 파일과 열쇠 파일을 함께 USB에 두고 여러 PC가 쓰는 경우:** 한 PC에서 바꾸면 USB의 두 파일이 함께 바뀌므로 다른 PC도 그대로 엽니다. 다른 곳에 남은 예전 금고 파일을 새 열쇠 파일로 처음 열면 "이 금고 파일은 이 열쇠 파일의 예전 열쇠로 저장되어 있습니다…"라고 묻습니다. 다른 PC에서 열쇠를 바꾼 뒤 이 PC에서 처음 여는 것이 맞을 때만 '예'를 누르세요.
- **멈춤과 위조:** 서버 사본의 열쇠를 이 PC가 모르면 멈출 뿐, 합치지도 덮어쓰지도 않습니다. 어느 PC에서도 열쇠를 바꾸지 않았는데 멈췄다면 서버 사본이 위조되었을 수 있습니다. 멈춤은 기록하지 않고 열 때마다 서버 사본으로 다시 판단하며, 다른 PC가 새 사본을 올리거나 새 열쇠 파일을 받으면 풀립니다. 서버의 최신 사본이 열쇠를 밝히지 않는 사본(손상, 다른 금고, 새 형식)으로 바뀌거나 동기화 폴더가 초기화되어도 멈춤은 그 사본과 함께 끝납니다.
- **예전 열쇠로 올라온 사본은 덮어씁니다:** 새 열쇠 파일을 아직 받지 않은 PC나 예전 열쇠 사본을 가진 사람이 예전 열쇠로 올린 사본은, 새 열쇠를 가진 PC가 합치지 않고 자기 상태로 덮어씁니다("예전 열쇠로 만든 서버 사본은 합치지 않고 이 PC의 상태로 덮었습니다…"). 예전 열쇠 사본으로 보낸 삭제나 수정이 새 열쇠의 금고에 들어오지 못하게 하기 위해서입니다. 이 PC에 없는 것이 없는 사본(이 PC가 열쇠를 바꾸기 전에 올린 자기 사본 등)은 알리지 않고 덮습니다. 덮인 사본은 서버 기록에 남고, 그 PC가 새 열쇠 파일을 받으면 그 PC의 변경은 그 뒤에 합쳐집니다.
- **두 PC에서 따로 바꿨다면(갈라짐):** 두 PC 모두 "두 PC에서 따로 열쇠를 바꿔 열쇠 파일이 갈라졌습니다…"로 멈춥니다. 한 PC에서 다른 PC의 열쇠 파일을 '새 열쇠 파일 받기'로 받으면 두 파일을 합친 새 열쇠 파일이 새 데이터 키로 생깁니다(두 PC가 모두 비밀번호를 바꿨다면 앞으로 쓸 비밀번호를 고릅니다). 그 결과를 다른 PC로 옮겨 받으면 그 PC에서는 이어진 새 버전이라 그대로 받습니다. PC가 셋 이상이면 같은 파일을 두 PC에서 따로 받지 말고, 가장 새 결과를 PC에서 PC로 옮기세요. 따로 합치면 합칠 때마다 새 데이터 키를 만들어 다시 갈라집니다.
- **서버 사본 덮어쓰기:** 열쇠를 바꾼 PC가 고장 났고 그 열쇠 파일도 열쇠 백업도 없어 어느 PC도 멈춤을 풀 수 없을 때(또는 서버 사본이 위조된 것이 확실할 때)만, '열쇠 관리'의 **서버 사본을 이 PC 상태로 덮어쓰기…**를 씁니다. 그 사본의 수정 번호, 열쇠 ID 앞 8자리, 서버 버전을 보여 주고 비밀번호(와 OTP)를 다시 확인한 뒤, 그 서버 버전 위에 이 PC의 상태를 올립니다. 덮인 사본은 합치지 않고 서버 기록(최근 200개)에만 남습니다. 이 결정은 이번 세션의 그 사본(같은 버전, 같은 바이트)에만 적용되고, 다음에 열 때나 다른 서버 사본이 오면 다시 판단합니다. 열쇠를 바꾼 PC가 살아 있었다면 그 PC가 이 PC의 사본을 예전 열쇠 사본으로 보고 다시 덮으며, 이 PC는 다시 멈춰 그 PC의 열쇠 파일을 받게 됩니다. 잃는 데이터는 없습니다. 마지막 수단인 까닭은, 다른 PC의 정당한 열쇠 변경 뒤에 그 PC에서 바꾼 내용을 이 PC가 덮어 버리기 때문입니다.
- **예전 열쇠 파일로 연 PC:** 이 PC가 전에 쓴 것보다 오래된 열쇠 파일로 열면("이 열쇠 파일은 이 고요 금고가 전에 본 것(수정 N)보다 오래되었습니다…") 서버 사본을 합치지도 덮어쓰지도 않고 올리지도 않으며, 서버 사본 덮어쓰기도 나오지 않습니다. 이때 서버 사본은 대개 이 PC가 전에 쓴 새 열쇠의 것이기 때문입니다. 이 PC가 전에 쓴 최신 열쇠 파일(열쇠 백업)로 다시 열거나 '새 열쇠 파일 받기'로 그 파일을 받으세요. 직접 되돌린 것이 맞다면 '열쇠 관리'의 **이 열쇠 파일이 맞습니다**를 누르세요. 누른 뒤 서버 사본이 더 나중의 열쇠로 저장되어 있으면 동기화가 다시 멈춥니다. 그 사본을 이 PC가 올렸다면 서버 사본 덮어쓰기로 이 PC의 상태를 올리세요.
- **확인 코드:** 0.9.0 열쇠 파일로 연 금고의 확인 코드는 열쇠 파일의 상태도 포함하므로, 두 PC가 같은 열쇠 파일을 받은 뒤에야 같아집니다. 다른 PC가 아직 받지 않았다면 '동기화됨'도 나오지 않습니다.

## 열쇠 파일 동기화 (보안 키 빌드, 실험)

보안 키 빌드([SECURITY_KEY.md](SECURITY_KEY.md))에서 보안 키를 켠 금고는, 금고마다 따로 **열쇠 파일 동기화** 를 켤 수 있습니다. 켜면 그 금고의 보안 키 열쇠 파일(`GOYOKS01`)도 서버를 통해 오가므로, 비밀번호 변경이나 키 제거 뒤에 USB로 옮길 필요가 없습니다. **대신 서버나 어느 PC의 동기화 SSH 키를 가진 사람에게 열쇠 파일은 더 이상 따로 지켜지는 요소가 아닙니다.** 남는 장벽은 비밀번호와 등록한 보안 키(와 PIN)뿐이고, 해킹된 서버는 올라간 모든 열쇠 파일을 보관한다고 가정해야 합니다. 기본 빌드와 보안 키를 켜지 않은 금고, 켰지만 열쇠 파일 동기화를 켜지 않은 금고에서는 열쇠 파일이 PC 밖으로 나가지 않습니다.

- **양쪽 모두 보안 키 빌드:** 금고 앱과 goyo-sync 둘 다 보안 키 빌드여야 합니다. 서버 스크립트는 같은 파일입니다(0.9.0).
- **강제 명령:** 그 금고를 쓰는 **모든 PC** 의 전용 키 줄에서 `serve` 뒤에 `--key-sync=<금고 ID>`를 붙입니다(32자리 소문자 16진수, `goyo-sync.exe --list`의 두 번째 칸. 여러 금고는 쉼표로, 공백 없이, 64개까지). 이 인자가 없는 연결은 열쇠 요청을 받지 않고(goyo-sync 상태 `nokeys`), 형식이 틀린 인자는 그 줄의 모든 요청을 거부합니다(`server`). 보안 키 빌드의 goyo-sync 설정 창에서 '강제 명령 줄…'을 누르면 이 줄을 보여 줍니다(공개 키 자리는 직접 채움, 저장되지 않음). 줄에는 목록의 금고 가운데 열쇠 파일 동기화를 쓰는 금고가 저절로 들어갑니다: 금고 파일이나 서버의 최신 사본이 `GOYOKS01` 열쇠 파일로 저장된 금고(다른 PC가 켠 경우 포함), 금고 앱이 열쇠 요청을 남긴 금고, 서버에 열쇠 파일이 있는 금고, 상태가 `nokeys`인 금고. 이 PC의 금고 파일이나 금고 앱의 요청이 아니라 서버 쪽 정보(서버 사본, 서버의 열쇠 파일, `nokeys`)로만 넣은 금고는 창에 따로 적어 줍니다. 직접 켠 금고가 맞는지 확인하고, 아니면 그 ID를 빼세요(동기화 키를 훔친 사람이 서버 사본으로 그렇게 보이게 할 수 있습니다). 목록이 비어 있는 새 PC에서는 먼저 '이 PC로 가져오기…'로 금고를 가져온 뒤 다시 누르라고 안내합니다. 아직 켜지 않은 금고를 미리 넣으려면 ID를 직접 붙이세요. 열쇠 파일 동기화를 켜고 끄는 곳은 고요 금고의 '열쇠 관리' 하나뿐이고, 설정 창에는 스위치가 없습니다.
  ```
  restrict,command="/usr/bin/python3 -I /home/<user>/.local/share/goyo-sync/goyo-sync-server.py serve --key-sync=0123456789abcdef0123456789abcdef" ssh-ed25519 AAAA… goyo-sync-pc1
  ```
  고요 금고에서 켠 뒤 '강제 명령 줄…'을 다시 눌러 그 줄로 바꾸세요. 줄을 바꾸면 도우미가 2분 안에 다시 확인합니다('저장하고 시작'으로 도우미를 다시 시작하면 바로). 다른 PC의 줄도 같은 ID로 바꿉니다. 끄기가 끝나 모든 PC가 받은 뒤에는 모든 줄에서 빼세요. 줄에 이름이 있는 금고는 서버에 열쇠 기록 기준이 남아, 그 줄의 동기화 키를 훔친 사람이 모든 PC의 업로드를 막을 수 있습니다.
- **`flock`이 되는 저장소:** 서버는 금고마다 `data/<금고 ID>/lock`에 `flock`을 걸고 그 안에서 열쇠 작업을 합니다. 열쇠 기록(`data/<금고 ID>/k/`)이 생긴 금고는 그 뒤 모든 연결의 업로드도 이 잠금 안에서 열쇠 기록과 맞춰 봅니다(맞지 않으면 KEY_BEHIND, 상태 `keyfile`). 그래서 저장소 폴더(`<스크립트 폴더>/data`)가 `flock`을 지원해야 합니다. 일반적인 Linux 로컬 파일 시스템은 모두 지원하고 NFS는 흉내 냅니다. 설치 때의 selftest가 확인합니다. 잠금을 20초 안에 얻지 못하면 `busy`(상태 `server`)로 답하고 도우미가 나중에 다시 합니다.
- **`k/` 지우기:** `data/<금고 ID>/k/`는 **그 금고를 동기화하는 PC가 하나도 없을 때만** 지우세요.
- **켜고 쓰기:** '열쇠 관리'의 **열쇠 파일 동기화 켜기…**. 다른 PC는 잠금 해제 뒤 '열쇠 관리'의 **받기…** 로 받습니다(제거는 잃어버린 키를 고르고, 추가·설정 변경은 바꾼 PC의 열쇠 확인 코드를 입력). 받기 전까지 그 PC는 올리지도 합치지도 않습니다. 보안 키를 켜지 않은 PC(다른 PC에서 나중에 보안 키를 켠 금고)는 '열쇠 관리'의 **서버의 새 열쇠 파일 받기…** 로 받습니다(그 PC의 코드나 '코드 없이 이 서버를 믿고 받기…', 그리고 새 열쇠 파일의 보안 키 하나).
- **새 PC:** 설정 창의 **이 PC로 가져오기…**가 금고 파일과 함께 서버의 열쇠 파일을 동기화 폴더에 가져옵니다(그 PC의 줄에도 `--key-sync`가 있어야 함). 고요 금고가 **서버에서 가져온 금고** 화면에서 다른 PC의 열쇠 확인 코드를 묻고 열쇠 파일을 금고 옆에 저장합니다. 열쇠 파일을 USB로 처음 옮겨도 됩니다. 그때도 처음 열 때 코드를 입력합니다.
- **끄기:** '열쇠 관리'의 **열쇠 파일 동기화 끄기…**(보안 키 끄기도 함께 끔). 이 PC가 서버에 열쇠 파일 삭제를 요청하고(보안 키 빌드의 goyo-sync가 실행될 때 보냄) 데이터 키를 바꿉니다. 끄기는 서버의 그 금고 열쇠 기록 전체를 끝내므로, 이 PC가 아직 받지 않은 다른 PC의 변경도 서버에서 사라집니다. 다른 PC는 이 열쇠 파일을 USB로 받아야 합니다. 다른 PC에서 다시 서버로 올려 되돌리지 마세요.
- **PC를 잃으면:** 그 PC의 `authorized_keys` 줄을 바로 지우세요. 그 키로는 열쇠 파일을 받거나 열쇠 동기화를 멈추게 할 수 있습니다(위조된 열쇠 파일을 받아들이게 하지는 못함). 서버 계정은 한 사람당 하나를 쓰세요.
- **동기화 폴더의 열쇠 파일:** `vault.goyo.sync\`에 `incoming.goyokeysync`(서버의 열쇠 파일 사본), `outgoing.goyokeysync`(올릴 요청), `prune.request`가 생길 수 있습니다. 고치지 마세요. 인증되지 않은 파일이라 이 폴더에 쓸 수 있는 사람은 동기화를 방해하거나 서버 기록을 지우게 할 수 있습니다.

자세한 설명(14가지 감수할 점, 키를 잃었을 때 모든 PC에서 할 일, 끄는 순서)은 [SECURITY_KEY.md](SECURITY_KEY.md)의 '열쇠 파일 동기화'에 있습니다.

## 8. 되돌리기: 서버 기록과 합치기 전 사본

서버는 금고마다 **최근 200개 버전**을 암호문으로 보관합니다. 내용을 바꿔 올릴 때마다 한 버전이 됩니다. 최신 버전 번호는 '이 PC로 가져오기…' 목록과 `goyo-sync.log`에서 볼 수 있습니다. 설정 창의 '이 PC로 가져오기…'는 최신 버전을 이 PC에서 동기화할 금고로 가져올 뿐이고, 되돌리기에는 쓰지 않습니다. 예전 버전은 명령줄로 받습니다(아래 '고급: 명령줄').

```powershell
.\goyo-sync.exe --fetch <32자리 금고 ID> 41 C:\Users\<you>\GoyoVault\from-server-v41.goyo | Out-Host
```

저장할 폴더는 이미 있어야 합니다. 받은 파일은 덮어쓰지 않습니다.

1. 받은 파일을 **백업 파일로 되살리기**로 **새 이름**(예: `vault-v41.goyo`)에 복원해 엽니다. 지금의 열쇠 파일과 비밀번호로 열립니다. 열쇠를 바꾼 뒤에도 최근 62번의 열쇠 변경 안에 저장된 버전(첫 변경 전의 버전은 언제나)은 지금의 열쇠 파일로 열리고, 그보다 오래된 버전은 그때의 열쇠 사본과 그때의 비밀번호로 엽니다.
2. 필요한 항목을 확인해 지금 금고에 다시 입력합니다.
3. 복원한 사본은 동기화하지 마세요. 같은 금고 ID라 목록에 넣으면 같은 서버 금고의 사본이 되고, 서버의 삭제 기록 때문에 그 항목이 다시 지워집니다. 삭제를 되살리는 합치기는 없습니다.

`vault.goyo.sync\pre-merge-*.goyo`도 같은 방법(백업 파일로 되살리기, 새 이름)으로 엽니다.

## 9. 동기화 끄기와 지우기

**한 PC에서 끄기:**
1. 설정 창에서 **Windows에 로그인하면 자동으로 시작**을 끄고(바로 적용) **중지**를 누릅니다. 먼저 멈춰야 합니다. 도우미가 돌고 있으면 폴더를 다시 만듭니다.
2. 금고 하나만 끄려면 그 금고를 **빼기**하고 **저장하고 시작**을 누릅니다. 모두 끄려면 도우미 설정과 기록(`goyo-sync.conf`, `goyo-sync.log*`)을 지웁니다. `goyo-sync.exe`는 열지 않으면 아무것도 하지 않으므로 남겨 둬도 됩니다.
3. `vault.goyo.sync` 폴더를 지웁니다. 남기고 싶은 `pre-merge-*.goyo`가 있으면 먼저 옮기세요.

금고는 동기화 형식 그대로 남고, 0.8.0 이상에서 오프라인으로 계속 열립니다. 0.7 이하 형식으로 되돌리는 기능은 없습니다.

**서버까지 모두 지우기:**
1. **모든 PC의 도우미를 먼저 멈추세요**(자동 시작 끄기와 중지). 하나라도 돌고 있으면 빈 서버에 자기 사본을 다시 올립니다.
2. 서버에서 `rm -rf ~/.local/share/goyo-sync`. 모든 암호화 기록이 지워집니다.
3. 서버의 `~/.ssh/authorized_keys`에서 goyo-sync 줄을 지웁니다.

## 10. 문제 해결

도우미의 상태는 동기화 폴더의 `status` 파일에 한 단어로 남고, 금고 앱과 설정 창의 목록은 그 단어로 표시만 고릅니다. 설정 창의 '연결 확인'과 '지금 동기화'(명령줄로는 `--check`, `--once`)가 지금 상태를 바로 알려 줍니다.

|상태|금고 앱 표시|뜻|할 일|
|---|---|---|---|
|`ok`|동기화됨 또는 올리는 중|정상입니다.|–|
|`idle`|표시 없음 또는 올리는 중|금고 앱이 아직 사본을 남기지 않아 이 금고의 ID를 모릅니다. 보통 동기화를 켜기 전입니다.|고요 금고에서 금고를 열고 동기화를 켜세요.|
|`offline`|연결 안 됨|서버 이름을 찾지 못함, 연결 시간 초과·거부, 경로 없음. 연결은 됐지만 제한 시간 안에 끝나지 않은 경우도 여기에 들어갑니다.|네트워크와 VPN을 확인하세요. 느린 회선이면 고급 설정의 제한 시간을 늘리세요. 변경은 이 PC에 남아 있다가 연결되면 올라갑니다.|
|`auth`|연결 안 됨, 인증 실패 알림|ssh.exe가 서버가 키를 거부했다고 알렸습니다(`Permission denied`). 서버나 셸 시작 파일이 같은 글을 출력하면 `server`입니다.|전용 키, `authorized_keys`, ssh-agent를 확인하고 `ssh my-server`(전용 키면 `ssh -i …`)로 직접 시험하세요. 전용 키 파일을 다른 계정도 읽을 수 있으면 ssh가 그 키를 무시하므로 goyo-sync가 그 연결을 쓰지 않고 이 상태가 됩니다(로그 `the dedicated SSH key was ignored: bad permissions`). '연결 확인'이 고치는 명령을 보여 줍니다(위 '전용 키와 강제 명령'). 15분마다 다시 시도합니다.|
|`hostkey`|연결 안 됨, 호스트 키 알림|서버 호스트 키가 `known_hosts`에 없거나 바뀌었습니다. ssh.exe 자신의 메시지로만 판단합니다. 서버가 출력한 글, 연결을 끊으며 보낸 사유, 버전 줄로는 이 상태가 되지 않습니다.|'연결 확인'을 누르세요. 처음 연결이면 지문을 비교해 받아 둘 수 있습니다. 바뀐 키라면 서버를 다시 설치한 것이 아닌 한 중간자 공격일 수 있습니다. 서버에서 직접 지문을 확인한 뒤에만 `known_hosts`를 고치세요. 확인 전에는 연결하지 않고, 15분마다 다시 시도합니다.|
|`nossh`|연결 안 됨|`System32\OpenSSH\ssh.exe`가 없습니다.|선택적 기능에서 'OpenSSH 클라이언트'를 추가하세요.|
|`server`|연결 안 됨|서버 스크립트가 없거나 오류를 냈거나, python이 없거나, 응답 형식이 맞지 않습니다. 로그인 셸이 출력하는 글이 너무 많아도 이렇게 됩니다. 업로드에 정직한 서버는 보내지 않는 충돌(CONFLICT) 응답이 온 경우(로그 `holding back uploads`)와, 원격에서 ssh 오류처럼 보이는 글을 출력한 경우도 여기에 들어갑니다. 서버가 이미 접속 8개를 처리하고 있을 때(로그에 `busy`)도 이 상태가 되며, 도우미가 30초부터 늘어나는 간격으로 다시 시도합니다.|'연결 확인'이 스크립트나 파이썬이 없는 경우를 따로 알려 줍니다. '서버에 설치·업데이트'로 다시 설치하고(selftest 포함), 고급 설정의 스크립트 경로·파이썬 명령을 확인하세요. 셸 시작 파일이 글을 출력한다면 대화형 셸에서만 출력하게 고치세요(예: `~/.bashrc` 맨 위에 `[[ $- == *i* ]] \|\| return`). 로그에 `holding back uploads`가 있으면 서버가 이 PC의 업로드를 막고 있을 수 있습니다(동결). 서버를 점검하세요. 변경은 이 PC에 남아 있고, 가장 새 파일만 30초에서 15분 간격으로 다시 시도합니다. 로그에 `server version N of this vault is damaged`가 있으면 서버의 `data/<금고 ID>/v/<N 12자리>.goyo`가 저장된 버전이 아닌 것(96바이트 미만이나 8 MiB 초과 파일, 폴더, 링크, FIFO)입니다. 로그에 적힌 그 경로의 파일을 지우거나 백업에서 되살리세요. `--fetch`도 같은 번호를 알려 줍니다.|
|`refused`|동기화 경고|올릴 파일이 도우미의 검사나 서버에서 거부되었습니다(링크가 된 파일, 다른 금고 ID, 서버의 금고 64개 한도, 저장하면 서버 디스크 여유 공간이 256 MiB보다 적어짐 등).|'로그 보기'에서 이유를 확인하세요. 금고를 다시 고치면 새 파일로 다시 시도합니다. 로그에 `a file of another vault`가 있으면(같은 경로에 새 금고를 만든 경우 등) '중지'를 누르고 `vault.goyo.sync` 폴더를 지운 뒤 '저장하고 시작'을 누르세요. 서버 디스크 공간 때문이면 서버에서 공간을 비운 뒤 금고를 다시 고치세요.|
|`config`|동기화 경고|`goyo-sync.conf`에 오류가 있어 도우미가 멈췄습니다.|설정 창을 열면 문제가 있는 줄을 알려 주고 읽을 수 있는 설정을 보여 줍니다. 고친 뒤 '저장하고 시작'을 누르세요.|
|`update`|동기화 경고, 새 형식 알림|서버 사본이 더 새로운 고요 금고 형식입니다(`GOYOVA05` 이상).|이 PC의 고요 금고와 goyo-sync를 업데이트하세요.|
|`oldserver`|동기화 경고, 서버 스크립트 알림|서버 스크립트가 0.9.0보다 오래되어 `GOYOVA04` 업로드를 거부했습니다(로그 `server refused GOYOVA04`). 설정 창 목록에는 '서버 스크립트 업데이트 필요'로 나옵니다.|'서버에 설치·업데이트'를 누르세요. 같은 파일을 10분마다, 그리고 도우미를 다시 시작할 때 다시 올립니다.|
|`keyfile`|동기화 경고, 열쇠 파일 알림|서버가 KEY_BEHIND로 업로드를 거부했습니다. 서버의 열쇠 파일 기록과 이 금고 사본의 열쇠가 맞지 않습니다. 서버에 그 금고의 열쇠 기록(`k/`)이 있을 때만, 곧 보안 키 빌드의 열쇠 파일 동기화를 쓰는 금고만 이렇게 답합니다. 설정 창 목록에는 '열쇠 파일 갱신 필요'로 나옵니다.|다른 PC에서 바꾼 열쇠 파일을 이 PC가 받으면 다시 올라갑니다. 그때까지 10분마다 다시 시도합니다.|
|`nokeys`|동기화 경고|(보안 키 빌드) 이 금고는 열쇠 파일 동기화를 쓰는데, 이 PC의 서버 연결이 그 금고의 열쇠 요청을 받지 않습니다(강제 명령에 `--key-sync=<금고 ID>` 없음). 설정 창 목록에는 '열쇠: 서버가 허용 안 함 · '강제 명령 줄…'의 줄로 바꾸세요'로 나옵니다. 전용 키 파일의 권한 때문에 ssh가 평소 키로 접속한 경우는 `auth`입니다.|서버의 `authorized_keys`에서 이 PC 줄을 설정 창의 '강제 명령 줄…'이 만든 줄로 바꾸세요('열쇠 파일 동기화'). 도우미가 2분 안에 다시 확인합니다. 금고 업로드는 그때까지 거부될 수 있습니다.|

'도우미 꺼짐'이면 설정 창에서 '저장하고 시작'을 누르고, 자동 시작이 켜져 있는지 확인하세요. 시작하자마자 끝나면 상태 줄과 '로그 보기'가 이유를 알려 줍니다.

**열쇠 파일이 더 새로운 형식일 때.** 금고를 열 때 "더 새로운 버전에서 만든 열쇠 파일입니다. 고요 금고를 업데이트하세요."가 나오면, 이 PC의 고요 금고보다 새로운 버전이 그 열쇠 파일을 썼습니다. 이 PC를 업데이트하세요. 보안 키로 잠긴 열쇠 파일은 [SECURITY_KEY.md](SECURITY_KEY.md)를 보세요.

**로그 `goyo-sync.log`.** 도우미 옆에 있고 '로그 보기'로 볼 수 있습니다. 256 KiB가 넘으면 `goyo-sync.log.1`로 넘어갑니다. 한 줄에 한 사건: UTC 시각, 금고 태그, 작업, 결과, 서버 버전, 주고받은 바이트, 걸린 시간, ssh 종료 코드, ssh 자신의 메시지 첫 줄(`ssh=`), 원격 쪽 표준 오류 첫 줄(`err=`). ssh 메시지는 호출마다 이 계정의 %TEMP%(쓸 수 없으면 도우미 옆)에 새로 만든 `goyo-sync.ssh-*.log`에 잠깐 쓰였다가 지워집니다. 도우미는 자기가 만든 바로 그 파일일 때만 읽고, 호출 중에 지워지거나 바뀌었으면 `ssh=`에 `ssh's own log was removed or replaced during the call`을 남깁니다(이때는 호스트 키·로그인 오류를 가려낼 수 없어 `server`로 표시). 도우미가 호출 도중 강제 종료되어 남은 파일은 다음 시작 때 지웁니다: 빈 파일은 1분, 나머지는 한 시간이 지난 뒤. 금고 내용은 절대 쓰지 않지만, ssh 메시지 줄에 서버 이름이, 다른 줄에 금고 파일 이름이 들어갈 수 있으니 공개할 때는 확인하세요. 설정 창이 한 일은 `window check`, `window trust`, `window install`, `window list`, `fetch` 줄로 남습니다. 자주 보는 줄:

|로그|뜻|
|---|---|
|`created the sync folder`|금고 옆에 동기화 폴더를 만들었습니다.|
|`pinned this vault ID from the app's first upload`|금고 앱이 처음 올린 사본으로 이 폴더의 금고 ID를 정했습니다.|
|`upload lost to server version N; the app merges it`|다른 PC가 먼저 올렸습니다. 금고 앱이 합친 뒤 다시 올립니다. 정상입니다.|
|`upload was already on the server`|지난번 업로드가 들어갔는데 응답만 잃었습니다. 정상입니다.|
|`server answered CONFLICT although …: it is holding back uploads`|서버가 이 PC의 업로드를 받지 않고, 이미 받은 사본(이 업로드가 기대한 버전, 또는 번호만 바꾼 것)으로 충돌이라고 답했습니다. 정직한 서버는 이렇게 답하지 않습니다. 상태는 `server`이고, 받은 사본은 다시 쓰지 않으며, 기다린 뒤 다시 시도합니다.|
|`server has no copy; uploading as the first version`|서버에 이 금고가 없어 첫 버전으로 올립니다.|
|`server was empty; re-uploaded the last known copy`|서버가 비어 있어(초기화·복원) 마지막으로 받은 사본을 다시 올렸습니다.|
|`server version went back A->B`|서버가 이전 버전을 보냈습니다. 금고 앱이 경고하고 이 PC의 상태를 다시 올립니다.|
|`incoming changed outside the helper`|동기화 폴더의 받은 사본이 바깥에서 바뀌거나 지워져 다시 받습니다.|
|`refused outgoing before upload: …`|올릴 파일이 검사에서 거부되었습니다. ssh는 실행하지 않았습니다.|
|`server refused GOYOVA04: its goyo-sync script is older than 0.9.0; use 'Install or update on server'`|서버 스크립트가 `GOYOVA04`를 모릅니다(`oldserver`). '서버에 설치·업데이트'를 누르세요.|
|`retrying a GOYOVA04 upload an older helper refused`|0.8 도우미가 거부했던 `GOYOVA04` 파일을 이번 실행에서 한 번 다시 올립니다. 정상입니다.|
|`server refused the upload: its key file for this vault has another state`|서버가 KEY_BEHIND로 거부했습니다(`keyfile`).|
|`state=config: …`|설정이나 폴더 문제입니다(금고 파일을 찾지 못함, 동기화 폴더나 그 안의 `helper.lock`이 링크 등). 그 폴더는 건드리지 않습니다.|
|`retry in N s`|실패 후 기다립니다. 30초에서 두 배씩 최대 15분, 인증·호스트 키 오류는 15분입니다. 금고를 고치면 한 번은 바로 시도합니다. 단, 서버가 업로드를 막고 있다고 판단한 뒤(`holding back uploads`)에는 기다림이 끝날 때 가장 새 파일만 시도합니다.|
|`banner=N`|서버 셸이 출력한 N바이트를 건너뛰었습니다(64 KiB까지는 문제없음). 셸 시작 파일(`~/.bashrc`, `~/.zshenv` 등)이 대화형 셸에서만 출력하게 고치면 사라집니다.|

## 11. 한계

- **서버가 다른 PC의 새 버전을 계속 숨기는 것(동결)은 알아챌 수 없습니다.** 다른 PC의 변경이 오지 않을 뿐입니다. 이 PC의 업로드를 거부하거나 이미 받은 사본으로 충돌이라고 답하는 동결은 `server`나 `refused` 상태로 드러나지만, 업로드를 받았다고 답하고 버리는 서버 앞에서도 이 PC는 '동기화됨'을 보입니다. 이런 경우와 서버가 PC마다 다른 사본을 보여 주는 것(분기)은 확인 코드가 달라지는 것으로만 드러납니다. 가끔 두 PC의 확인 코드를 비교하세요.
- **서버가 금고를 연 시각을 알 수 있는 경우가 하나 있습니다.** 아직 올라가지 않은 변경이 있는데 서버에서 새 사본이 오면, 금고 앱은 합친 뒤(닫혀 있었다면 다음에 열 때) 변경을 다시 올립니다('무엇이 오가고, 무엇이 PC에 남나요').
- **새 PC가 서버에서 받는 첫 사본은 서버를 믿습니다.** 확인 코드를 비교하거나 USB로 옮기세요.
- **처음 연결의 호스트 키는 그 순간의 네트워크를 믿습니다.** 지문을 서버에서 직접 확인한 것과 비교하세요.
- 서버가 예전 버전을 보내도 항목은 지워지지 않고 경고가 나옵니다. 다만 그 사실을 알아챌 수 있는 것은 그 금고를 이미 더 새 버전으로 맞춰 본 PC뿐입니다.
- **OTP 번호 재사용 거부는 PC마다만 보장합니다.** OTP만 바뀐 열기는 올리지 않으므로, 한 PC에서 쓴 번호는 그 PC의 다음 내용 변경이 동기화될 때까지 다른 PC에서 아직 받아들여질 수 있습니다. 그래도 비밀번호, 열쇠 파일, 지금 유효한 번호가 모두 필요합니다.
- **열쇠를 바꾸면 예전 열쇠 사본은 서버를 통해 더 쓸 수 없습니다.** 0.9.0에서 비밀번호를 바꾼 뒤에는, 새 열쇠 파일을 받은 PC가 예전 열쇠로 올라온 사본을 합치지 않고 덮어쓰므로 예전 열쇠 사본과 그때의 비밀번호로 보낸 삭제나 수정은 들어오지 않습니다. 다만 바꾸기 전의 서버 버전과 백업은 계속 읽을 수 있고, 예전 사본을 다시 올려 동기화를 방해할 수는 있습니다(서비스 거부. 덮어쓰입니다). 금고 폴더에도 쓸 수 있는 사람이 예전 금고 파일을 제자리에 넣는 것은 바꾼 뒤 그 금고를 아직 열지 않은 PC에서만 통하고, 그때도 "예전 열쇠로 저장되어 있습니다"라고 먼저 묻습니다. 다른 PC에서는 열지 않습니다. 새 열쇠 파일을 아직 받지 않은 PC는 그때까지 예전 열쇠를 쓰므로 0.8과 같습니다.
- **열쇠를 바꾸기 전에는 0.8과 같습니다.** 예전 열쇠 사본과 그때의 비밀번호를 가진 사람은 서버를 통해 진짜 삭제나 수정을 보낼 수 있습니다. 같은 ID에 다른 글을 넣어 바꿔치기해도 사라진 항목으로 셉니다. 합치기 전 사본, 알림, 서버 기록으로 드러나지만 막지는 못합니다. 금고를 열 때마다 조금씩(예: 한 개씩)만 지우면 합치기 전 사본은 생기지 않고 매번 '삭제 N개' 알림만 나옵니다. 서버에 쓸 수 있는 사람은 200개 기록도 새 업로드로 밀어낼 수 있습니다.
- **비밀번호를 바꾸면** 그 PC의 열쇠 파일과 데이터 키가 바뀌고, 다른 PC는 그 열쇠 파일을 '새 열쇠 파일 받기'로 받을 때까지 동기화를 멈춥니다(위 '열쇠를 바꾼 뒤'). 열쇠를 바꾼 PC를 더 쓸 수 없고 그 열쇠 파일도 없으면 서버 사본 덮어쓰기만 남는데, 그것은 사람의 판단에 맡깁니다.
- OneDrive Files On-Demand처럼 재분석 지점(reparse point)이 붙은 폴더는 동기화 폴더로 쓰지 않습니다. README대로 금고는 클라우드 폴더에 두지 마세요.
- 서버 기록 200개는 서버가 지키는 것이라, 적대적인 서버는 지울 수 있습니다. 금고·열쇠 백업은 여전히 직접 하세요.
- 도난당한 동기화 키(강제 명령)로도 서버 접속 8자리를 계속 붙잡아 모든 PC의 동기화를 멈출 수 있습니다(서비스 거부). 서버 디스크를 여유 256 MiB 아래로 채우거나 금고를 64개보다 많이 만들 수는 없습니다.
- 삭제·수정 기록은 금고마다 최대 65,536개이고 줄어들지 않습니다. 다 차면 수정·삭제가 거부됩니다. 보통 쓰임새로는 닿기 어려운 수입니다.
- 같은 금고 ID의 사본(복원한 백업 등)을 두 곳에서 동기화하면 둘 다 같은 서버 금고의 사본이 됩니다.
- 동기화를 켜기 전에 PC마다 따로 고친 사본을 각각 켜면, 한쪽에서 지우거나 고친 항목이 다시 나타납니다. 동기화 전 형식에는 삭제 기록이 없기 때문입니다('4. 동기화 켜기').
- 같은 사용자 권한의 악성코드는 동기화와 관계없이 금고·열쇠 파일을 복사하거나 비밀번호를 기록할 수 있습니다. 동기화가 이 위험을 바꾸지는 않습니다.
- **열쇠 파일 동기화(보안 키 빌드)를 켠 금고는** 위 '열쇠 파일은 PC 밖으로 나가지 않습니다'가 성립하지 않습니다. 서버가 숨긴 열쇠 변경(동결)은 그 PC에서 사용자가 무언가 할 때까지 그 PC에 닿지 않고, 서버의 열쇠 파일 삭제는 정직한 서버에서만 의미가 있습니다([SECURITY_KEY.md](SECURITY_KEY.md)).

## 고급: 명령줄과 goyo-sync.conf

설정 창이 하는 일은 모두 명령줄로도 할 수 있습니다. PowerShell에서는 `goyo-sync.exe`가 창이 없는 프로그램이라, `| Out-Host`를 붙여야 끝날 때까지 기다려 결과를 보여 주고 `$LASTEXITCODE`도 채웁니다.

### 명령

|명령|하는 일|
|---|---|
|(인자 없음)|설정 창을 엽니다. 이미 열려 있으면 그 창을 앞으로 가져옵니다.|
|`--background`|백그라운드 동기화(창 없음). 2초마다 금고 앱이 남긴 변경을 확인해 바로 올리고, `interval`마다 서버의 새 버전을 받아 옵니다. 같은 폴더의 goyo-sync는 하나만 실행됩니다. 자동 시작과 '저장하고 시작'이 이렇게 실행합니다.|
|`--once`|모든 금고를 한 번 동기화하고 결과를 출력합니다.|
|`--check`|읽기만 합니다: 설정, `ssh.exe`, 서버 연결, 금고별 동기화 폴더·금고 ID·서버 버전.|
|`--list`|서버의 금고 목록: 태그(`3FA2-C1D0`), 32자리 금고 ID, 최신 버전, 크기, 저장 시각(UTC).|
|`--fetch <금고 ID> <head 또는 N> <새 파일.goyo>`|서버의 버전 하나를 새 파일로 저장합니다. 있는 파일은 덮어쓰지 않습니다. 고요 금고의 **백업 파일로 되살리기**로 엽니다.|
|`--autostart on` / `off`|로그인할 때 자동 시작을 켜거나 끕니다(현재 사용자 레지스트리의 Run 값 `GoyoSync`, `"<goyo-sync.exe>" --background`). `off`는 실행 중인 도우미도 멈춥니다. 폴더를 옮기면 다시 `on` 하거나 설정 창에서 저장하세요.|
|`--stop`|실행 중인 도우미를 멈춥니다.|
|`--self-check`|보호 설정과 설정 창 생성을 점검합니다(배포 검사용).|

종료 코드는 0 정상, 1 오류, 2 설정 오류입니다. 화면 언어는 같은 폴더의 `goyo-vault.lang`(금고 앱에서 고른 언어)을 따릅니다.

명령줄만으로 설정할 때의 순서입니다. 서버 설치는 '서버에 설치·업데이트'가 보내는 위 한 줄 명령을 그대로 쓰거나, 직접 복사합니다. 직접 복사할 때도 설정 창과 같이 `.new`로 받아 그 사본의 selftest가 `PASS`를 출력한 뒤에만 `mv`로 바꿉니다. 그래서 `scp`가 중간에 끊겨도 쓰던 스크립트는 그대로 남습니다.

```powershell
ssh my-server "mkdir -p ~/.local/share/goyo-sync && chmod 700 ~/.local/share/goyo-sync"
scp .\server\goyo-sync-server.py my-server:.local/share/goyo-sync/goyo-sync-server.py.new
ssh my-server "cd ~/.local/share/goyo-sync && chmod 700 goyo-sync-server.py.new && python3 -I goyo-sync-server.py.new selftest && mv -f goyo-sync-server.py.new goyo-sync-server.py"
.\goyo-sync.exe --check | Out-Host
.\goyo-sync.exe --autostart on | Out-Host
.\goyo-sync.exe --background
```

이 경우 서버 호스트 키는 처음 한 번 `ssh my-server`로 직접 접속해 지문을 확인하고 받아 두어야 합니다. `--check`·`--once`와 백그라운드 도우미는 모르는 키로 연결하지 않습니다.

### goyo-sync.conf

설정 창이 '저장하고 시작'으로 쓰는 파일이고, `goyo-sync.conf.example`을 복사해 메모장으로 고쳐도 됩니다. 한 줄에 `이름 = 값` 하나씩 씁니다. `#` 뒤는 주석이라, 값에 `#`를 쓸 수 없습니다(`#`가 들어간 경로의 금고는 동기화할 수 없습니다). 값 바로 뒤에 붙은 `#`(예: `vault = C:\x\v#1.goyo`)는 경로가 그 자리에서 잘리지 않도록 그 줄의 오류로 거부합니다. 주석은 앞에 공백을 두세요. 모르는 이름, 잘못된 값, 같은 이름이 두 번 나오면 도우미가 멈추고(종료 코드 2), 동기화 폴더가 이미 있는 금고는 금고 앱에 '동기화 경고'가 표시됩니다. 손으로 고쳤다면 도우미를 다시 시작하세요(설정 창의 '저장하고 시작', 또는 `--stop` 후 `--background`).

|이름|기본값|뜻|
|---|---|---|
|`host`|(필수)|ssh 대상. `%USERPROFILE%\.ssh\config`의 별칭이나 `[사용자@]호스트`. 영문·숫자·`. _ -`만 쓰고, `-`로 시작할 수 없습니다.|
|`remote`|`.local/share/goyo-sync/goyo-sync-server.py`|서버 스크립트 경로(서버 홈 폴더 기준). 영문·숫자·`. _ / ~ + -`, `.`·`..`인 경로 조각 불가|
|`python`|`python3`|서버의 파이썬 명령. 영문·숫자·`. _ / + -`|
|`identity`|(비움)|전용 ssh 개인 키의 절대 경로. 적으면 그 키만 씁니다. `.goyokey`·`.goyo` 파일은 거부합니다.|
|`interval`|`60`|서버의 새 버전을 확인하는 간격(초), 30~3600.|
|`timeout`|`120`|ssh 호출 한 번의 제한 시간(초), 30~600.|
|`vault`|(1개 이상)|동기화할 금고 파일의 절대 경로. 한 줄에 하나, 최대 8개. 열쇠 파일(`*.goyokey`)은 거부합니다.|

설계와 검토 기록: [FORMAT.md](FORMAT.md), [SECURITY_REVIEW.md](SECURITY_REVIEW.md).
