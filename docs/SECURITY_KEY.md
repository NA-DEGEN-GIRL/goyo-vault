# 보안 키 (실험 기능)

<b>한국어</b> · [English](SECURITY_KEY.en.md)

> [!WARNING]
> **실험 기능: 실제 보안 키로 검증하지 않았습니다. 기본 빌드와 릴리스 ZIP에는 들어 있지 않습니다.**
>
> 이 기능은 가짜 보안 키(테스트용 흉내)로만 시험했습니다. 실제 키에서 꼭 확인해야 할 점은 맨 아래 [실제 보안 키 점검표](#실제-보안-키-점검표)에 있고, 하나도 실행하지 않았습니다. **중요한 금고에는 아직 쓰지 마세요.** 쓰더라도 가짜 값으로 만든 시험 금고에서 먼저 익히세요.

## 무엇을 하나요

보안 키(YubiKey 등 FIDO2)를 켜면 열쇠 파일을 **비밀번호와 등록한 보안 키 둘 다로** 잠급니다. 금고를 열 때 금고 파일, 열쇠 파일, 비밀번호에 더해 등록한 보안 키 하나를 연결하고 터치해야 합니다(PIN을 켰다면 키의 PIN도).

보안 키는 복호화에 직접 참여합니다. 그래서 열쇠 파일과 비밀번호를 함께 가진 사람도 등록한 키 없이는 열 수 없고, 열쇠 파일만으로는 비밀번호를 오프라인으로 추측할 수도 없습니다.

안에서는 비밀이 둘로 나뉩니다.

- **키세트 비밀**: 무작위 32바이트. 등록한 보안 키가 내놓는 값(hmac-secret)으로만 꺼낼 수 있습니다. 열쇠 파일을 쓸 때마다 새로 만듭니다.
- **데이터 키**: 금고를 암호화하는 키. 키세트 비밀 **과** 비밀번호가 함께 있어야 꺼낼 수 있습니다.

> **등록한 보안 키를 모두 잃거나 초기화하면 이 금고는 영원히 열 수 없습니다.** 비밀번호와 열쇠 파일이 있어도, 만든 사람도, 개발자도 열 수 없고 복구 코드도 없습니다. 2개 이상 등록하고 예비 키는 다른 곳에 두세요. 키 번호(보안 키 1, 2…)를 실물 키에 적어 두세요.

## 보안 키 빌드 만들기

설치용 ZIP(`python scripts/package_release.py`)은 언제나 보안 키 기능이 없는 기본 빌드입니다. 보안 키 빌드는 직접 만듭니다.

1. README의 '설치'대로 소스를 받고 기본 ZIP을 한 번 만들어 `GoyoVault` 폴더를 준비합니다.
2. 같은 소스 폴더에서 보안 키 빌드를 만듭니다.
   ```powershell
   cargo build --release --locked --bins --features security-key
   ```
3. `target\release\goyo-vault.exe --self-check | Out-Host`가 `security-key: EXPERIMENTAL build`와 `salt self-test: PASS`를 보여 주는지 확인합니다. Windows의 WebAuthn을 쓸 수 있으면 `WebAuthn API <번호>`도 나옵니다.
   Microsoft Defender가 방금 빌드한 서명 없는 실행 파일을 막거나 격리하면, README '직접 빌드하기'의 'Windows Defender·SmartScreen이 막을 때'대로 보호 기록에서 그것이 직접 빌드한 파일인지 확인한 뒤에만 복원·허용하세요.
4. `target\release\goyo-vault.exe`와 `goyo-sync.exe`를 `GoyoVault` 폴더의 같은 이름 파일 위에 복사합니다. 두 파일은 **함께** 바꾸세요. 열쇠 파일 동기화는 보안 키 빌드의 goyo-sync만 합니다. 그러면 그 폴더의 `SHA256SUMS.txt`(기본 빌드의 해시 목록)는 이 두 파일과 더 이상 맞지 않습니다.

기본 빌드로 되돌아가려면 먼저 보안 키 빌드에서 **보안 키 끄기**를 하세요. 기본 빌드는 보안 키로 잠긴 열쇠 파일을 열지 않습니다(아래 [기본 빌드가 보안 키 열쇠 파일을 만나면](#기본-빌드가-보안-키-열쇠-파일을-만나면)). 그다음 이 금고를 쓰는 **다른 PC마다, 아직 보안 키 빌드인 채로** 그 변경을 받으세요(끈 PC의 새 열쇠 파일을 USB로 옮겨 '새 열쇠 파일 받기', 열쇠 확인 코드 입력). 그 PC는 받은 뒤에만 기본 빌드로 바꾸세요. 받기 전의 PC는 이 금고를 보안 키 금고로 기억하고 있어서, 어느 빌드든 비밀번호만으로 여는 열쇠 파일을 거부합니다. 그때 남는 방법은 그 PC의 열쇠 기록(`goyo-vault.keys`)을 지우는 것뿐이고, 그러면 모든 금고의 기록이 사라집니다.

**Windows의 `webauthn.dll`.** 보안 키 빌드는 보안 키가 있는 열쇠 파일을 열 때와 보안 키를 켜거나 등록할 때만 System32의 `webauthn.dll`을 불러옵니다(정적 import는 없고, 보안 키 없는 금고는 불러오지 않습니다). 이때 그 DLL이 스스로 쓰는 System32 DLL이 함께 들어옵니다: 불러올 때 combase, oleaut32, rpcrt4, windows.storage, advapi32, sechost, msvcrt, ntmarta, 처음 호출할 때 cryptngc, winsta, bcryptprimitives, 첫 터치 때 dpapi, bcrypt, crypt32. 금고의 암호화는 이 DLL들을 쓰지 않습니다. 터치와 PIN을 묻는 창은 Windows가 띄우는 별도 창입니다.

## 켜기

**새 금고.** '만들기'에서 **보안 키로도 잠그기 (실험)** 를 켜고 만듭니다. 키의 PIN은 늘 씁니다(아래 PIN).

**지금 쓰는 금고.** '열쇠 관리'에서 **비밀번호도 바꾸기 (권장)** 를 확인하고 현재 비밀번호를 넣은 뒤 **보안 키 켜기** 를 누릅니다. 데이터 키도 함께 바뀝니다.

- **비밀번호도 바꾸기를 권하는 이유:** 보안 키를 켜기 전에 만든 열쇠 파일과 그 백업(0.8 열쇠 파일, 예전 비밀번호 변경 때의 `GOYOKE03`)은 비밀번호만으로 열립니다. 비밀번호를 그대로 두면 그런 사본을 주운 사람은 그 비밀번호를 오프라인으로 계속 추측할 수 있고, 맞히면 남는 장벽은 등록한 보안 키(와 PIN)뿐입니다. 비밀번호를 그대로 둘 거라면 그 예전 사본을 지우세요.
- **등록:** 키마다 Windows 창이 세 번 열립니다(등록 한 번, 확인 두 번). 매번 같은 키를 터치하고 PIN을 입력합니다. PIN이 없는 키는 첫 창에서 Windows가 PIN을 정하게 합니다.
- **NFC:** NFC 리더로 쓸 키는 Windows 창이 열리기 **전에** USB에서 뽑아 두세요. 창이 열릴 때 USB에 꽂혀 있으면 Windows가 그 연결을 쓰고, 리더에 대도 응답하지 않습니다. NFC에서도 PIN은 화면에 입력한 뒤 키를 리더에 댑니다.
- **2개 이상, 한 PC에서 함께 등록하세요.** 함께 등록한 키끼리 서로 **짝** 을 맺습니다(아래). 하나만 등록하면 열 때마다 빨간 경고가 나옵니다.
- **키마다 다른 PIN** 을 정하세요. 모든 키에 같은 PIN을 쓰면, 잃어버린 키와 그 PIN을 아는 사람이 다른 키를 잠깐 손에 넣는 것만으로 그 키를 복제할 수 있습니다.
- **키 번호를 실물에 적으세요.** 화면은 키를 '보안 키 1, 2…'로만 부릅니다.
- 등록이 끝나면 **열쇠 백업** 을 하세요. 열쇠 파일을 잃으면 보안 키와 비밀번호가 있어도 열 수 없습니다.

### 보안 키 없이 만든 금고에 나중에 켜기

0.8에서 만든 금고나 보안 키 없이 쓰던 금고(열쇠 파일 `GOYOKE01`/`GOYOKE02`, 비밀번호를 바꾼 적이 있으면 `GOYOKE03`)도 위와 같이 켭니다.

- **켜기 전에** "보안 키를 켜면 앞으로 이 금고를 열 때마다 비밀번호와 함께, 등록한 보안 키 하나를 연결해 터치하고 그 키의 PIN을 입력합니다…"가 먼저 나옵니다. 등록할 키를 모두 그 PC에 준비하고, 이 금고를 다른 PC에서도 쓴다면 그 PC의 고요 금고도 보안 키 빌드여야 한다는 안내입니다.
- **바뀌는 것:** 항목과 금고 ID는 그대로이고, 데이터 키가 바뀌어 새 열쇠 파일(`GOYOKH01`)을 씁니다(열쇠 확인 코드도 새로 생깁니다). 예전 OTP 금고라면 열쇠 파일에 남아 있던 OTP 비밀은 이때 지워집니다. 켜기 전의 열쇠 파일로는 그 뒤에 저장한 내용이 열리지 않고, 그 PC는 이제 열 때마다 등록한 키를 터치합니다. 중간에 끊겨도(전원 등) 다음 잠금 해제가 예전 열쇠 파일이나 새 열쇠 파일 중 하나로 열리게 마무리합니다. 나중에 보안 키를 끄면 다시 비밀번호만으로 여는 `GOYOKE03`이 되고 항목은 모두 남습니다.
- **켠 뒤** 다른 PC가 할 일을 창으로 한 번 알려 줍니다. 동기화하는 금고라면 다른 PC는 이 PC의 새 열쇠 파일을 받을 때까지 동기화를 멈춥니다(그동안의 변경은 그 PC에만 저장되었다가 받은 뒤 합쳐집니다).

**다른 PC마다**(그 PC도 보안 키 빌드여야 합니다):

- **USB로:** 켠 PC의 새 열쇠 파일을 USB로 가져가 '열쇠 관리' › **새 열쇠 파일 받기…** 로 받습니다. 켠 PC의 열쇠 확인 코드를 입력하고(코드를 입력하기 전에는 무엇이 바뀌었는지 보여 주지 않습니다), 새 열쇠 파일에 등록된 보안 키 하나를 터치합니다. 그 PC의 현재 비밀번호로 다시 확인합니다.
- **서버로(열쇠 파일 동기화):** 켠 PC에서 **열쇠 파일 동기화** 도 켰다면(아래 '열쇠 파일 동기화') USB가 필요 없습니다. 보안 키가 없는 PC는 "다른 PC에서 이 금고에 보안 키를 켜 동기화를 멈췄습니다. 새 열쇠 파일은 서버로 옵니다. '열쇠 관리'의 '서버의 새 열쇠 파일 받기…'로 받으세요…"라고 알리고, '열쇠 관리'에 "다른 PC에서 보안 키를 켠 새 열쇠 파일(수정 N)이 서버에 있습니다…"와 **서버의 새 열쇠 파일 받기…** 가 나옵니다. 현재 비밀번호를 넣고 누르면, 켠 PC의 열쇠 확인 코드를 묻고(아래 '코드 없이 이 서버를 믿고 받기…'도 있음), 새 열쇠 파일에 등록된 보안 키 하나를 터치하게 한 뒤, 무엇이 바뀌는지 보여 주고 열쇠 파일 동기화의 위험 질문을 묻습니다. 받으면 그 PC도 같은 열쇠 파일(`GOYOKS01`)을 쓰고 동기화가 이어집니다. 그 PC의 goyo-sync도 보안 키 빌드여야 하고, 그 PC의 강제 명령 줄에도 `--key-sync=<금고 ID>`가 있어야 서버의 열쇠 파일이 그 PC에 옵니다. 서버에 아직 열쇠 파일이 없으면 이 버튼은 나오지 않고 USB로 받습니다.
- **0.8 열쇠 파일을 쓰던 PC:** 0.8 열쇠 파일에는 열쇠 확인 코드가 없어서, 다른 PC에서 보안 키를 켠 사본이 동기화로 온 금고를 열면 먼저 "이 PC는 이 열쇠 파일을 아직 확인하지 않았습니다…이 열쇠 파일은 예전(0.8) 형식이라 열쇠 확인 코드로 확인할 수 없습니다"가 나옵니다. 코드 칸은 없습니다(맞을 수 없는 코드를 묻지 않음). 다른 PC에서 보안 키를 켰고 이 파일이 이 PC에서 쓰던 열쇠 파일이 맞을 때만 **코드 없이 이 열쇠 파일 믿기…** 를 누르고(위험 질문, 기본 '아니요'), 그다음 위처럼 '열쇠 관리'에서 받습니다. 그 전에는 항목을 고치거나 올리지 않습니다.
- **기본 빌드 PC:** 보안 키 열쇠 파일을 받을 수 없어 "다른 PC에서 이 금고에 보안 키를 켜서 동기화를 멈췄습니다. 이 고요 금고 빌드는 보안 키를 지원하지 않아…"로 멈춥니다. 그 PC를 보안 키 빌드로 바꾸고 받으세요(위 '보안 키 빌드 만들기').

**보안 키 안의 자리.** 등록할 때마다 키의 '검색 가능한 자격 증명' 자리를 하나 씁니다(YubiKey 5는 펌웨어에 따라 약 25개나 100개). 자리가 다 차면 새 등록이 실패하니, 뺀 키나 실패한 등록의 항목은 키 제조사의 관리 도구로 지우세요(YubiKey는 `ykman fido credentials delete`, Windows에서는 관리자 권한 명령 창에서, 키의 PIN 필요). 항목 이름은 `Goyo Vault <금고 ID 앞 8자리> key <번호> <등록 시각>`이고, '열쇠 관리'의 '등록 표시'와 시각이 같은 항목만 이 금고가 쓰는 것입니다. Windows 설정의 패스키 목록은 이 PC에 저장된 패스키용이라 보안 키 안의 항목은 보이지 않을 것으로 예상합니다(확인하지 않음).

## PIN

- **PIN은 늘 씁니다.** PIN을 끄는 선택은 없습니다. Windows는 보안 키 안에 항목을 만드는 등록에서 PIN이 없는 키에 PIN을 정하게 하고, 키에 PIN이 생긴 뒤에는 앱이 PIN 확인을 요구하지 않아도 매번 PIN을 묻습니다(실제 키로 확인). 그래서 PIN 없는 방식은 Windows에서 지킬 수 없습니다. 등록은 늘 PIN 확인 필수와 PIN 필수 보호(credProtect 3, 필수)로 하고, 열쇠 파일은 늘 PIN 방식으로 씁니다.
- 키의 PIN은 **Windows 보안 창** 에 입력합니다. 이 창은 다른 프로세스라 고요 금고의 화면 캡처 차단 대상이 아닙니다.
- PIN을 8번 틀리면 키가 잠깁니다. 잠긴 키를 FIDO 초기화하면 그 키의 등록이 사라져 이 금고를 열 수 없습니다.
- 출시 전 시험 빌드가 PIN 없이 만든 열쇠 파일(이 기능은 그 방식으로 배포된 적이 없습니다)도 지금처럼 열리고 바뀝니다. 그런 파일에 새로 추가하는 키는 PIN으로 등록되며, 열쇠 파일 동기화는 모든 키가 PIN으로 등록된 PIN 방식 파일에서만 켤 수 있습니다. 그런 금고는 보안 키를 끈 뒤 다시 켜면 PIN 방식이 됩니다.

## 열기와 '열쇠 관리'

로그인 화면이 "이 열쇠 파일은 보안 키가 필요합니다(등록 N개)"라고 알리고, '잠금 해제'를 누르면 Windows 보안 창이 열립니다. 등록한 키 아무거나 연결하고 PIN을 입력한 뒤 터치하면 됩니다(NFC 리더로 쓸 키는 먼저 USB에서 뽑으세요). Windows 창은 늘 고요 금고 창에 속합니다. 소유 창 없이 부르면 Windows가 바로 거부하며(0x80090027), 그때는 "Windows가 보안 키 요청을 거부했습니다"라고 알립니다.

'열쇠 관리' 아래쪽에 보안 키 부분이 있습니다.

- 상태 줄: `보안 키: 켜짐 · PIN 사용 · 4개 등록`.
- **다른 키를 모두 대신할 수 있는 키:** 다른 모든 키와 짝을 맺은 키입니다. 키를 잃었을 때 이 키 하나로 바로 뺄 수 있습니다. '없음'이면 '짝 맺기'를 하세요.
- 키 목록: 키마다 등록일, 이번에 연 키인지, 등록 표시(키 안의 항목 이름에 들어가는 시각), 짝 상태('모든 키와 짝', '보안 키 4와 짝 맺기 필요', '일시 정지(짝 맺기 필요)', '복제됐을 수 있음' 등).
- 단추: **키 추가**, **짝 맺기…**, **모든 키 새로 잠그기…**, **잃어버린 키 제거…**, **키 빼기…**, **보안 키 끄기**. 아래 칸의 현재 비밀번호는 모든 단추가 다시 확인하는 데 씁니다.
- **열쇠 확인 코드**(`E5 · XXXX-XXXX-XXXX-XXXX`): 다른 PC가 이 PC의 키 추가나 설정 변경을 받을 때 이 코드를 입력합니다. 현재 데이터 키로만 계산되므로, 잃어버린 키를 가진 사람도 맞출 수 없습니다.

## 짝 맺기

같은 자리에서 함께 터치한 키끼리 **짝** 을 맺습니다. 짝을 맺은 키는 서로를 대신해 새 열쇠를 전할 수 있습니다. 그래서 다른 모든 키와 짝을 맺은 키가 하나 있으면, 비밀번호 변경, 키 추가, 키 제거를 **그 키 하나, 터치 한 번** 으로 할 수 있고 다른 키를 옮길 필요가 없습니다.

- **처음에 모든 키를 한 PC에서 함께 등록하세요.** 그러면 모든 키가 서로 짝을 맺습니다.
- **나중에 산 키** 는 지금 있는 키 하나로 추가합니다(그 키 터치 1번 + 새 키 등록 3번). 새 키는 바로 금고를 엽니다. 그 자리에 꽂혀 있는 다른 키가 있으면 함께 터치해 짝을 맺습니다.
- **다른 장소의 키와는** 나중에, 급하지 않을 때 새 키를 그곳으로 한 번 가져가 **짝 맺기** 를 하세요(만나는 키마다 터치 1번). 그 전까지 새 키는 만나지 못한 키를 대신할 수 없습니다. 그 장소에서 키를 빼면 새 키가 **일시 정지** 될 수 있습니다.
- **일시 정지:** 이번에 터치한 키와 짝이 없어 새 열쇠를 전할 수 없는 키입니다. 제거나 합치기를 할 때, 그 키를 이름으로 알려 주고 동의를 받은 뒤에만 생깁니다. 일시 정지된 키로는 열 수 없고, 그 키와 짝을 맺은 키가 나중에 무언가를 쓰거나 **짝 맺기** 를 하면 다시 쓸 수 있습니다.
- 짝 기록이 손상되었으면(목록의 '짝 기록 손상') 두 키를 한곳에서 다시 짝 맺으세요.

## 키를 잃어버렸을 때

**한 줄 요약: 손에 있는 PC에서 '잃어버린 키 제거'를 하고, 이 금고를 쓰는 다른 PC마다 그 변경을 받거나 같은 제거를 하세요.**

### 손에 있는 PC에서

1. '열쇠 관리' › **잃어버린 키 제거…**
2. 잃어버린 키를 **모두** 고릅니다.
3. **대략 언제 잃어버렸나요?** 모르면 비워 둡니다(그 경우 아래 검토 목록이 전체 기록을 보여 줍니다).
4. **PIN이나 비밀번호를 다른 사람이 알 수 있나요?** 보았거나, 키와 함께 적어 두었거나, 다른 곳에도 같은 것을 썼다면 '예'. '예'나 '모름'이면
   - 같은 PIN을 쓰는 다른 키를 고르라고 합니다. 고른 키는 '복제됐을 수 있음'으로 표시됩니다.
   - **비밀번호도 함께 바꾸기 (권장)** 가 켜집니다. 새 비밀번호를 정하세요. 그러면 잃어버린 키를 가진 사람이 만든 열쇠 파일은 새 비밀번호로 열리지 않습니다. 열쇠 파일 동기화를 켠 금고에서는 다른 PC를 새 비밀번호로 열면 서버의 새 열쇠 파일로 열리므로, 서버가 이 변경을 숨기면 새 비밀번호가 어디서도 먹히지 않아 드러납니다(아래 [동결의 한계](#동결의-한계)).
5. 화면 오른쪽의 '터치할 키'를 확인하고, 현재 비밀번호를 넣은 뒤 **제거** 를 누르고 남은 키 하나를 터치합니다.

**터치 한 번으로 끝나고, 이 PC는 그 순간부터 보호됩니다.** 새 키세트 비밀과 새 데이터 키를 만들고, 잃어버린 키에는 아무것도 주지 않습니다. 키를 다른 장소로 옮길 필요가 없습니다. 키는 자기 자신의 제거를 승인할 수 없으므로, 잃어버린 키로 만든 열쇠 파일은 그 키를 뺄 수 없습니다.

- 터치할 키와 짝이 없는 키가 있으면 그 키를 이름으로 알려 주고 **일시 정지** 할지 묻습니다. 그 키가 지금 곁에 있으면 '그 키도 함께 터치'를 누르세요.
- 잃어버린 키하고만 짝을 맺은 키(예: 그 키로 추가한 예비 키)가 있으면 함께 뺄지 묻습니다(권장). 다른 장소에서 쓰는 유일한 키일 수 있다면 남겨 두세요.

### 다른 PC마다

**어떤 설계로도, 다른 PC에서 아무것도 하지 않은 채 제거가 그 PC에 닿게 할 수는 없습니다.** 그 PC에서 무언가 할 때까지, 서버가 이 변경을 숨기면(동결) 그 PC는 잃어버린 키와 그 PIN, 비밀번호를 함께 가진 사람에게 열려 있습니다. 다른 PC마다 둘 중 하나를 하세요.

- **변경을 받기.** 받기 전에 그 PC는 **잃어버린 키를 고르라고** 하고, 고르기 전에는 무엇이 바뀌었는지 보여 주지 않습니다. 고른 키가 실제로 빠진 키와 정확히 같아야 통과합니다(아래 [다른 PC가 받는 관문](#다른-pc가-받는-관문)). 잘못 고르면 다시 고를 수 없고, 처음 PC에 보이는 열쇠 확인 코드를 입력하는 방법만 남습니다.
  - **열쇠 파일 동기화를 켠 금고:** 그 PC를 열 때 받습니다. 제거할 때 비밀번호를 바꿨다면 **새 비밀번호** 로 여세요. 그 PC의 열쇠 파일로는 열리지 않으므로 "서버의 새 열쇠 파일로 열어 볼까요?"가 나오고, '예'를 누르고 잃어버린 키를 고르면 같은 터치로 받고 열립니다. 예전 비밀번호로 열면 열린 직후 잃어버린 키를 고르라고 하고, 받을 때 새 비밀번호를 묻습니다. '나중에'를 눌렀다면 '열쇠 관리'의 **받기…** 로 받습니다.
  - **열쇠 파일이 PC에만 있는 금고:** 처음 PC의 새 열쇠 파일을 USB로 가져가 '열쇠 관리' › **새 열쇠 파일 받기…** 로 받고 잃어버린 키를 고릅니다. 한 번 옮기면 끝납니다.
- **그 PC에서도 직접 제거하기.** 그 PC를 지금 바로 보호해야 하면(옮길 수 없거나 서버를 믿을 수 없을 때) 그 PC에서도 **잃어버린 키 제거** 를 하세요. 그 PC는 바로 보호됩니다. 두 PC의 열쇠 파일은 갈라지므로 나중에 합칩니다.
  - 열쇠 파일 동기화를 켠 금고: 두 PC가 같은 상태에서 제거만 했다면 서버에 늦게 올린 PC가 다음 잠금 해제 때 스스로 합칩니다(아래 '쓰는 동안'). 한쪽에서 비밀번호도 바꿨다면 그 PC의 '열쇠 관리'에 "서버의 열쇠 파일과 갈라짐 · [받기…]로 합치세요"가 나오고, **받기…** 로 합칩니다.
  - 열쇠 파일이 PC에만 있는 금고: 두 PC가 서로의 열쇠 파일을 한 번씩 '새 열쇠 파일 받기'로 받으면 동기화가 다시 이어집니다.

### 그다음

- **동기화로 들어온 변경 확인.** 잃어버린 키 제거가 이 PC에 들어오면(직접 했든 받았든), 잃어버린 날 하루 전부터 다른 PC에서 동기화로 들어온 변경 목록이 나옵니다. 잃어버린 키를 가진 사람이 서버를 통해 바꿔 넣었을 수 있으니 계좌번호, 지갑 주소, 복구 이메일, 로그인 주소처럼 바뀌면 위험한 항목을 확인하고 **확인함** 을 누르세요. 그 전에는 이 PC의 금고 내용을 서버에 올리지 않고(열쇠 파일은 올라갑니다), 열 때마다 다시 보여 줍니다. 목록은 이 PC에서 보안 키 빌드가 합친 것만 담고, 인증된 기록이 아니며, 날짜가 실제와 가까워야 도움이 됩니다.
- **같은 PIN을 쓰던 키**('복제됐을 수 있음')는 모든 키가 한곳에 모일 때 **모든 키 새로 잠그기** 를 하거나, 그 키를 빼고 다시 등록하세요. 보안 키가 남의 손에 있었을 수 있으면 비밀번호만 바꾸지 말고 '모든 키 새로 잠그기'나 그 키 빼기 후 다시 등록을 하세요.
- **이미 저장된 것은 보호되지 않습니다.** 키를 빼거나 바꾸면 그 뒤에 저장하는 내용만 보호됩니다. 그 전의 내용은 잃어버린 키와 그 PIN, 비밀번호, 예전 열쇠 파일 사본(열쇠 파일 동기화를 켰다면 서버 기록)을 가진 사람이 계속 읽을 수 있습니다. 그럴 수 있다면 금고 안의 비밀 자체(실제 비밀번호, 키, 자금 위치)를 바꾸세요.
- **서버의 예전 기록 지우기.** 열쇠 파일 동기화를 켠 금고에서 제거가 끝나면, 서버에 남은 변경 전 금고 기록(최근 200개)을 지울지 묻습니다. 정직한 서버에서만 의미가 있습니다. 해킹된 서버는 이미 복사해 두었다고 보세요.
- **더 쓰지 않는 키 정리**: 아래 [키 빼기와 더 쓰지 않는 키](#키-빼기와-더-쓰지-않는-키).

### 한 장소의 키를 모두 잃었을 때

그 장소의 PC는 키가 그곳에 갈 때까지 열 수 없습니다. 어떤 설계로도 마찬가지입니다. 제거 자체는 다른 장소에서 터치 한 번으로 됩니다.

1. 다른 장소의 PC에서 **잃어버린 키 제거** 로 잃어버린 키를 모두 고르고 남은 키 하나를 터치합니다.
2. 같은 PC에서, 그곳의 키를 꽂아 둔 채 **키 추가** 로 새 키를 등록합니다(그곳의 키와 바로 짝을 맺으므로 나중에 짝 맺으러 갈 필요가 없습니다).
3. **새 키와 그 PC의 새 열쇠 파일을 함께** 가져가고, 그 PC의 열쇠 확인 코드를 적어 둡니다. 열쇠 파일 동기화를 켠 금고라면 열쇠 파일은 가져가지 않아도 됩니다: 키를 잃은 장소의 PC에서 평소처럼 '잠금 해제'를 누르고, Windows 보안 창(그 PC가 아는 키를 찾는 창)을 취소하면 "…그 키로 열어 볼까요?"가 나옵니다. [터치]를 누르고 새 키를 터치한 뒤 적어 온 코드를 입력하면 열리고, 새 열쇠 파일도 받습니다.
4. 열쇠 파일을 가져갔다면 키를 잃은 장소의 PC에서 로그인할 때 가져간 열쇠 파일을 고르고 새 키로 엽니다. 그 PC가 본 적 없는 키(새 키)가 들어 있는 열쇠 파일이라 열쇠 확인 코드를 물으면 적어 온 코드를 입력합니다. 그 PC의 원래 열쇠 파일에는 새 키가 없어서 그 파일로는 열 수 없고, '새 열쇠 파일 받기'는 금고를 연 뒤에만 쓸 수 있기 때문입니다.

## 예: 키 4개, 장소 2곳

집(A)에 PC_A와 보안 키 1·2, 사무실(B)에 PC_B와 보안 키 3·4가 있고 두 PC가 이 금고를 동기화합니다.

**준비.** 네 키를 한 PC에서 함께 등록합니다(키마다 Windows 창 3번, 모두 12번). 네 키가 모두 서로 짝을 맺습니다. 열쇠 백업을 하고, 다른 PC에는 열쇠 파일을 USB로 옮깁니다(그 PC는 처음 열 때 이 PC의 열쇠 확인 코드를 묻습니다). 키 1·2를 집에, 키 3·4를 사무실에 둡니다.

**집에서 키 1을 잃음.**
1. PC_A: **잃어버린 키 제거** → 보안 키 1 → 날짜 → "PIN이나 비밀번호를 다른 사람이 알 수 있나요?" **모름**(비밀번호 변경이 켜짐, 새 비밀번호를 정함) → 현재 비밀번호 → **키 2를 한 번 터치**. PC_A는 이 순간부터 보호됩니다. 키를 옮길 필요는 없습니다.
2. PC_B, 열쇠 파일 동기화를 켠 경우: 키 3(또는 4)으로 엽니다. **새 비밀번호** 로 열면 "서버의 새 열쇠 파일로 열어 볼까요?"에 '예'를 누르고, 예전 비밀번호로 열면 열린 직후 묻습니다. 보안 키 1을 고르면(그 전에는 아무것도 보여 주지 않음) 잠금 해제의 그 터치로 받습니다(예전 비밀번호로 열었다면 받을 때 새 비밀번호를 입력). 두 번째 터치는 없습니다. '나중에'를 눌렀을 때만 '열쇠 관리'의 **받기…** 로 받습니다. 받고 나면 두 PC의 열쇠 확인 코드가 같고, 동기화로 들어온 변경 확인이 나옵니다.
3. PC_B, 열쇠 파일이 PC에만 있는 경우: PC_B는 "다른 PC에서 이 금고의 열쇠를 바꿔 동기화를 멈췄습니다…"라고 알리고 동기화를 멈춥니다. 다음에 USB로 PC_A의 새 열쇠 파일을 가져와 **새 열쇠 파일 받기** → 보안 키 1을 고름 → 키 3 터치 → 새 비밀번호. 바로 보호해야 하면 그 전에 PC_B에서도 **잃어버린 키 제거**(보안 키 1, 키 3 터치)를 하고, 나중에 두 PC가 서로의 열쇠 파일을 한 번씩 받습니다.

**합계.** 옮긴 키 0개. 집에서 터치 1번. 사무실에서는 평소 잠금 해제에 더해 키 고르기 1번(열쇠 파일 동기화면 터치는 잠금 해제의 것으로 끝남, USB로 옮기면 터치 1번 더).

**나중에 예비 키 5를 집에서 추가.**
1. PC_A: **키 추가**, 키 2 터치 1번 + 키 5 등록 3번. 키 5는 바로 금고를 엽니다. 목록에 '보안 키 5: 보안 키 3, 4와 짝 맺기 필요'.
2. PC_B는 이 추가를 받을 때 PC_A의 열쇠 확인 코드를 입력합니다(사진으로 찍어 두면 편합니다). 열쇠 파일 동기화면 다음 잠금 해제 때 코드를 물어 받고('나중에'를 눌렀다면 '열쇠 관리'의 **받기…**), 아니면 PC_A의 새 열쇠 파일을 USB로 옮겨 **새 열쇠 파일 받기** 로 받습니다(그때까지 PC_B는 동기화를 멈춥니다). 키 추가는 고르기가 아니라 코드로만 받습니다.
3. 급하지 않을 때 키 5를 사무실로 한 번 가져가 PC_B에서 **짝 맺기** 로 키 5·3·4를 터치합니다(3번). PC_A는 이 짝 기록을 확인 없이 받습니다. 열쇠 파일 동기화면 다음 잠금 해제 때 묻지 않고 받고, 아니면 PC_B의 열쇠 파일을 USB로 옮겨 **새 열쇠 파일 받기** 로 받습니다(짝 맺기도 열쇠 파일을 바꾸므로, 그때까지 PC_A는 동기화를 멈춥니다).
4. 그 방문 전에는: 사무실에서 키 3으로 비밀번호를 바꾸려 하면 키 3은 키 5에 새 열쇠를 전할 수 없어 키 5도 함께 터치하라고 합니다(키 5가 없으면 취소하고 집에서 키 2로 하세요). 사무실에서 키를 빼면 키 5는 동의를 받은 뒤 일시 정지됩니다.

**두 번째 분실이 짝 맺기 방문 전에 오면** 키 5가 홀로 남을 수 있습니다. 그래서 방문을 너무 미루지 마세요.

## 다른 PC가 받는 관문

다른 PC에서 보안 키 구성(키 추가·제거)이나 설정(PIN, 열쇠 파일 동기화, 보안 키 끄기)을 바꾼 열쇠 파일은, 이 PC가 **확인한 뒤에만** 받습니다. 확인 전에는 이 PC가 서버에 아무것도 올리지 않고 받은 서버 사본도 합치지 않습니다. 로그인할 때 열쇠 파일 자체가 바뀌어 있었다면(여러 PC가 함께 쓰는 열쇠 USB 등) 확인 전에는 항목도 고치거나 저장하지 않습니다.

- **제거만 있는 변경:** "다른 PC에서 보안 키가 제거되었습니다. 이 PC에서 고르기 전에는 무엇이 바뀌었는지 보여 주지 않습니다. 잃어버렸거나 뺀 키를 모두 고르세요." 고른 키가 실제로 빠진 키와 **정확히** 같아야 통과합니다. 한 번 틀리면 그 변경에는 다시 고를 수 없고 코드만 남습니다. 잃어버린 키를 가진 사람이 만든 변경은 그 키 자신을 뺄 수 없으므로, 사용자가 그 키를 고르면 위조 변경은 통과하지 못합니다.
- **키 추가, 설정 변경, 처음 보는 키의 제거, 새 PC, USB로 옮긴 열쇠 파일:** 바꾼 PC의 '열쇠 관리'에 지금 보이는 **열쇠 확인 코드** 를 입력합니다(`E{수정 번호} · XXXX-XXXX-XXXX-XXXX`). 바꾼 PC는 변경 직후 이 코드를 창으로 보여 줍니다("다른 PC가 이 변경을 받을 때 이 코드가 필요합니다. 휴대폰으로 찍어 두세요."). 코드는 '열쇠 관리'에도 계속 보입니다. 다른 PC에서 코드가 틀리면 입력한 코드가 칸에 남아 고쳐 쓸 수 있습니다. 코드가 다른 수정 번호로 시작하면 그 사이 그 PC에서 열쇠를 다시 바꾼 것입니다.
- **나중에** 를 누르면 확인을 미루고, '열쇠 관리'의 **받기…** 로 다시 할 수 있습니다.
- **받지 않기…** 는 위조된 것이 확실할 때만 쓰세요. 실제 변경이라면 이 PC는 계속 멈춘 채 남습니다(나중에 USB로 받을 수 있습니다).
- 코드를 입력해야 하는 변경을 한 PC를 더 쓸 수 없어 코드를 볼 수 없다면(디스크 고장 등), 열쇠 파일 동기화를 쓰는 금고에서는 '열쇠 관리'의 **다른 PC가 없어 이 PC 상태로 올리기…** 로 이 PC의 열쇠 파일을 그 변경보다 높은 수정 번호로 다시 올립니다(위험 질문, 기본 '아니요', 비밀번호와 터치 1번). 그 변경(예: 그 PC에서 추가한 키)은 사라지니 필요하면 다시 하세요. 이 PC의 키를 제거하는 변경, 이 PC가 모르는 키의 제거 기록이 든 변경에는 이 버튼이 나오지 않습니다. 그때는 '잃어버린 키 제거'를 하거나 열쇠 파일 동기화를 끄세요. 그 PC가 마지막으로 올린 금고 사본은 이 PC 상태로 덮어씁니다. 열쇠 파일을 이 PC에만 두던 PC에서 하면 이 PC도 열쇠 파일 동기화를 켜게 되며, 먼저 그 동의를 묻습니다.
- 확인할 다른 PC가 없으면 코드 없이 믿고 받을 수 있지만, 진짜인지 확인할 방법은 없습니다(모두 위험 질문, 기본 '아니요'). 제거할 때 비밀번호도 바꿨다면 위조 열쇠 파일은 새 비밀번호로 열리지 않습니다. 코드 없이 믿는 곳은 셋뿐입니다.
  - **코드 없이 받기 (이 서버를 믿음)…**: 새 PC가 서버에서 가져온 열쇠 파일(아래 '새 PC').
  - **코드 없이 이 열쇠 파일 믿기…**: USB로 옮긴 열쇠 파일이나 0.8 열쇠 파일을 처음 열 때의 확인.
  - **코드 없이 이 서버를 믿고 받기…**: 보안 키가 없는 PC가 '서버의 새 열쇠 파일 받기…'에서, 다른 PC가 보안 키를 켜고 서버에 올린 열쇠 파일을 받을 때(위 '보안 키 없이 만든 금고에 나중에 켜기'). 서버에서 온 그 파일에만 쓰이고(USB로 가져온 파일에는 없음), 이 PC가 자기 열쇠 파일을 확인한 뒤에만 됩니다. 받은 뒤 상태 줄이 "코드 없이 이 서버를 믿고 받았습니다…"라고 알리니, 그 PC를 다시 쓸 수 있게 되면 두 PC의 열쇠 확인 코드를 비교하세요.
- 이와 달리 **열쇠 변경 자동 적용 (이 서버를 믿음)** 은 이미 확인한 열쇠 파일에서 이어지는 변경을 묻지 않고 받는 설정입니다(아래 '열쇠 변경 자동 적용').

## 키 빼기와 더 쓰지 않는 키

- **키 빼기…** 는 잃어버리지 않은 키를 빼는 것입니다(예: 고장, 교체). 남는 키 하나를 터치하면 끝나고 데이터 키가 바뀝니다. 동기화로 들어온 변경 확인은 나오지 않습니다. 비밀번호 변경은 선택입니다.
- **더 쓰지 않는 키에서는 이 금고의 등록을 지우세요.** 지우지 않으면 그 키와 예전 열쇠 파일 사본, 비밀번호로 예전 내용을 열 수 있습니다. 등록 하나만 지우려면 키 제조사의 관리 도구를 쓰세요(YubiKey는 `ykman fido credentials delete`, Windows에서는 관리자 권한 명령 창에서, 키의 PIN 필요). PIN이 없는 키는 먼저 PIN을 정해야 하는데, 그 키를 PIN 없이 쓰는 다른 고요 금고가 있으면 PIN을 정한 뒤 그 금고가 열리지 않을 수 있습니다.
- **FIDO 초기화** 는 그 키를 다른 곳(다른 고요 금고, 웹사이트 패스키)에 쓰지 않을 때만 하세요. 초기화는 그 키의 모든 패스키와 다른 금고의 등록까지 지우며, 그 키가 다른 금고의 유일한 키라면 그 금고는 영영 열 수 없게 됩니다.

## 모든 키 새로 잠그기

누군가 PIN을 알고 보안 키를 잠깐 가져가 터치했을 수 있을 때(복제 의심) 씁니다. 등록한 키가 **모두** 한곳에 있어야 하고, 키마다 터치하고 마지막에 한 번 더 확인 터치를 합니다. 키별 값, 짝 기록, 키세트 비밀, 데이터 키를 모두 새로 만들어, 그 전에 몰래 얻은 키 응답으로는 그 뒤의 열쇠 파일을 열 수 없습니다. 다른 PC는 열쇠 확인 코드를 입력해야 받습니다. 비밀번호도 노출되었을 수 있으면 끝난 뒤 비밀번호도 바꾸세요.

## 보안 키 끄기

**보안 키 끄기** 를 하면 데이터 키를 바꾸고 비밀번호와 열쇠 파일만으로 열리는 열쇠 파일(`GOYOKE03`)을 씁니다(더 약해집니다). 뺀 키의 기록은 열쇠 파일에 남아, 나중에 다시 켜도 예전 키가 돌아오지 않습니다. 다른 PC는 이 변경을 받을 때 코드를 입력합니다. 열쇠 파일 동기화를 쓰던 금고면 열쇠 파일 동기화도 함께 꺼지고(아래), 다른 PC는 열쇠 파일을 USB로 받아야 합니다. 더 쓰지 않는 키는 위처럼 정리하세요.

## 이 PC의 기록

- **이 PC의 열쇠 기록**(`%LOCALAPPDATA%\GoyoVault\goyo-vault.keys`, README의 '이 PC의 열쇠 기록')은 보안 키 금고에서는 **꼭 필요합니다**. 이 PC가 이 금고를 보안 키로 연 것, 이 PC가 확인한 상태, 기다리는 관문, 검토, '복제됐을 수 있음' 표시를 기억합니다. 비밀은 없고 인증되지 않은 기록입니다.
- 이 기록 때문에 맞는 열쇠 파일이 열리지 않으면(갈라진 파일, 빠진 제거 기록 등) 보안 키 빌드는 파일 전체를 지우는 대신 로그인 화면(관문을 기다리는 동안에는 '열쇠 관리'에도)의 **이 금고의 기록 지우고 다시 확인…** 을 제공합니다. 비밀번호와 터치로 연 뒤 이 금고의 기록만 지우고, 그 열쇠 파일을 처음 보는 파일로 다시 확인합니다(다른 PC의 열쇠 확인 코드 입력). 예전 열쇠 파일이나 위조된 파일일 수 있으면 누르지 마세요. 파일 전체를 지우면 다른 모든 금고의 기록과 기다리는 관문도 함께 사라집니다(기다리던 검토는 아래 기록 때문에 계속 남습니다).
- **합치기 기록**(`%LOCALAPPDATA%\GoyoVault\goyo-vault.merges\<금고 ID>.log`): 보안 키와 동기화를 함께 쓰는 금고에서, 동기화로 들어온 변경마다 항목 ID와 시각만 적습니다(제목·내용 없음). 동기화로 들어온 변경 확인 목록이 이 기록을 씁니다. PC마다 따로 있고 동기화되지 않으며, 이 폴더에 쓸 수 있는 사람은 줄을 지울 수 있습니다.

## 열쇠 파일 동기화 (선택, 실험)

보안 키 빌드에서 금고마다 따로 켜는 기능입니다. 기본은 꺼져 있고, 켜면 열쇠 파일도 서버를 통해 PC 사이를 오가므로 비밀번호 변경이나 키 제거 뒤에 열쇠 파일을 USB로 옮길 필요가 없습니다. **대신 서버에 닿는 사람에게는 열쇠 파일이 더 이상 따로 지켜지는 요소가 아닙니다.**

|방식|빌드|서버가 가진 것|서버 자료로 풀 수 있는 사람|
|---|---|---|---|
|1. 보안 키 없음|기본|금고 암호문뿐|없음(열쇠 파일이 PC 밖으로 나가지 않음)|
|2. 보안 키, 열쇠 파일은 PC에만|보안 키 빌드|금고 암호문뿐|없음(열쇠 파일이 PC 밖으로 나가지 않음)|
|3. 보안 키 + 열쇠 파일 동기화|보안 키 빌드|금고 암호문 **과** 올린 모든 보안 키 열쇠 파일. 해킹된 서버는 모두 보관한다고 가정합니다.|**비밀번호와 등록한 보안 키, 그 PIN** 을 함께 가진 사람. 서버나 어느 PC의 동기화 SSH 키를 가진 사람에게 열쇠 파일은 따로 지켜지는 요소가 아닙니다. 예전 열쇠 파일은 해킹된 서버에 영원히 남으므로, 뺀 키와 예전 비밀번호로 그 키가 빠지기 전까지의 기록을 열 수 있습니다.|

**해킹된 서버는 올라간 모든 것을 보관한다고 가정합니다.**

### 무엇을 감수하나요 (14가지)

1. 약속이 바뀝니다: '서버에는 절대 풀 수 없는 암호문만 있다'가 '서버는 비밀번호와 PIN이 걸린 등록 보안 키가 둘 다 없으면 풀 수 없다'가 됩니다.
2. 서버나 동기화 SSH 키가 뚫리면 공격자에게 남은 장벽은 비밀번호와 보안 키+PIN 둘뿐입니다. 열쇠 파일이라는 세 번째 장벽은 사라집니다.
3. 한 번 서버에 올라간 열쇠 파일은 그때 서버에 접근할 수 있던 사람이 계속 가질 수 있습니다. 키 제거나 비밀번호 변경은 그 뒤에 저장하는 것만 보호합니다. 보안 키를 잃었고 비밀번호도 노출됐을 수 있다면 비밀 자체를 바꾸세요(자금 이동, 키 재발급).
4. 키를 제거한 뒤에는 모든 PC가 그 변경을 받아야(잃어버린 키를 고르거나 코드를 입력해야) 제거가 끝납니다. 두 PC의 열쇠 확인 코드가 같으면 같은 열쇠 상태입니다.
5. 새 PC는 첫 사용 전에 다른 PC의 열쇠 확인 코드를 입력해야 합니다. 첫 사본은 USB로 옮기는 것을 권하고, 서버에서 받아 시작할 수도 있습니다(아래 '새 PC').
6. 서버 사본은 백업이 아닙니다. 열쇠 파일 USB 백업과 보안 키 2개 이상은 계속 필수입니다. 복구 코드는 없습니다.
7. PIN은 필수입니다. 비밀번호와 다른 6자 이상으로 정하세요. 8번 틀리면 키가 잠기고, 초기화하면 그 키는 이 금고를 열 수 없습니다.
8. 더 쓰지 않는 보안 키에서는 이 금고의 등록을 지우세요(FIDO 초기화는 다른 곳에 쓰지 않는 키만). 그대로 두면 비밀번호와 함께 서버에 남은 예전 열쇠 파일을 열 수 있습니다.
9. PC를 잃어버리면 그 PC의 `authorized_keys` 줄을 즉시 지우세요. 서버 계정은 한 사람당 하나를 쓰세요. 같은 계정의 다른 동기화 키는 내 열쇠 파일도 받을 수 있습니다.
10. 열쇠 파일 사본이 각 PC의 동기화 폴더(`incoming.goyokeysync`)에 놓입니다. 열쇠 파일을 USB에만 두던 분리 효과가 줄어듭니다.
11. 휴대폰 패스키와 Windows Hello는 쓸 수 없습니다. USB나 NFC 보안 키만 됩니다.
12. 열쇠가 바뀌면 다른 PC는 다음 잠금 해제 때 받습니다(그때 받지 않았다면 '열쇠 관리'의 [받기…]). 제거는 잃어버린 키를 고르고, 키 추가나 설정 변경은 바꾼 PC의 코드를 입력합니다. 확인 전에는 무엇이 바뀌었는지 보여 주지 않습니다. 그 PC에서 '열쇠 변경 자동 적용 (이 서버를 믿음)'을 켰다면 고르기와 코드 없이 받습니다(기본 꺼짐, 아래 '열쇠 변경 자동 적용').
13. 보안 키를 끄거나 열쇠 파일 동기화를 끄면 다른 PC는 다시 USB로 열쇠 파일을 받아야 합니다.
14. 이득: 변경 뒤 USB로 옮길 필요가 없습니다. 단 서버가 정직할 때만이며, 서버가 공격받으면 동기화가 멈춥니다(데이터를 잃지는 않습니다).

### 서버 준비

1. 서버 스크립트를 0.9.0으로 업데이트합니다(goyo-sync 설정 창의 '서버에 설치·업데이트').
2. 금고 ID(32자리 소문자 16진수)를 확인합니다: `goyo-sync.exe --list | Out-Host`의 두 번째 칸.
3. 그 금고를 쓰는 **모든 PC** 의 전용 키 줄([SYNC.md](SYNC.md)의 '전용 키와 강제 명령')에서 `serve` 뒤에 `--key-sync=<금고 ID>`를 붙입니다. 금고가 여럿이면 쉼표로 잇습니다(64개까지, 공백 없음). 보안 키 빌드의 goyo-sync 설정 창이 이 줄을 만들어 줍니다: 금고 목록 아래의 **강제 명령 줄…** 을 누르면, 그 PC의 파이썬 명령과 스크립트 경로, 목록의 금고 가운데 열쇠 파일 동기화를 쓰는 금고(금고 파일이나 서버의 최신 사본이 `GOYOKS01` 열쇠 파일로 저장됨, 고요 금고가 열쇠 요청을 남김, 서버에 열쇠 파일이 있음, 상태 `nokeys`)의 ID가 저절로 든 줄이 나옵니다(Ctrl+C로 복사, 공개 키 자리는 직접 채움). 이 표시는 저장되지 않고, 설정 창에는 열쇠 파일 동기화 스위치가 없습니다(켜고 끄는 곳은 고요 금고의 '열쇠 관리'뿐). 아직 켜지 않은 금고는 줄에 들어가지 않으니, 켜기 전에 넣으려면 ID를 직접 붙이세요. 켠 뒤에 넣었다면 '열쇠 관리'에 '서버가 이 금고의 열쇠 파일 동기화를 받지 않습니다'가 보이다가, 줄을 바꾸면 goyo-sync가 2분 안에 다시 확인합니다.
   ```
   restrict,command="/usr/bin/python3 -I /home/<user>/.local/share/goyo-sync/goyo-sync-server.py serve --key-sync=0123456789abcdef0123456789abcdef" ssh-ed25519 AAAA… goyo-sync-pc1
   ```
   - PC마다 전용 키를 따로 쓰세요. PC 한 대를 잃으면 그 줄만 지웁니다.
   - 글자가 하나라도 틀리면(대문자, 31자리, 빈 `--key-sync`) 서버가 그 줄의 **모든** 요청을 거부하고 도우미는 `server` 상태가 됩니다.
   - **열쇠 파일 동기화를 켜기 직전에** 넣고, 끄기가 끝나 모든 PC가 받은 뒤에는 모든 줄에서 빼세요. 줄에 이름이 있는 금고는 어느 방식이든 서버에 열쇠 기록 기준이 남아, 그 줄의 동기화 키를 훔친 사람이 모든 PC의 업로드를 막을 수 있기 때문입니다(관리자가 `data/<금고 ID>/k/`를 지울 때까지).
4. 서버의 저장소 폴더(`~/.local/share/goyo-sync/data`)는 `flock`을 지원해야 합니다. 일반적인 Linux 로컬 파일 시스템은 모두 지원하고 NFS는 흉내 냅니다. 설치 때 selftest가 그 폴더의 잠금을 확인합니다.
5. `data/<금고 ID>/k/`는 **그 금고를 동기화하는 PC가 하나도 없을 때만** 지우세요.

### 켜기

- 조건: 보안 키가 켜져 있고 PIN 모드이며 모든 키가 PIN으로 등록됨, 그 금고의 동기화가 켜져 있음, 이 Windows가 키의 연결 방식(USB/NFC)을 알려 줌, 보안 키 빌드의 goyo-sync가 최근 10분 안에 서버를 확인함, 서버에 이 금고의 열쇠 파일이 아직 없음(다른 PC가 켰다면 그 파일을 [받기…]로 받으세요).
- '열쇠 관리' › **열쇠 파일 동기화 켜기…** → 위 14가지를 10가지로 줄인 위험 질문(기본 '아니요') → 비밀번호와 터치 1번. 열쇠 파일을 다시 쓰고(데이터 키는 그대로) goyo-sync가 서버에 올립니다.
- 켜고 끄는 곳은 고요 금고의 이 버튼 하나입니다. 그 옆 한 줄이 이 금고의 열쇠 파일을 어디에 두는지 보여 줍니다: **열쇠 파일: 이 PC에만 보관 (다른 PC에는 USB로)** 또는 **열쇠 파일: 서버로 동기화 (실험)**.
- 다른 PC는 이 변경을 받을 때 이 PC의 열쇠 확인 코드를 입력하고, 같은 위험 설명을 봅니다.
- 열쇠 파일 동기화를 쓰는 금고에서 열쇠를 바꾼 PC(켜기, 키 추가·제거, 짝 맺기, 모든 키 새로 잠그기, 비밀번호 변경, 이 PC 상태로 올리기)는 잠금 해제마다 상태 줄에 "다른 PC들이 이 열쇠 변경을 받았는지 확인 전입니다…"(제거면 "…이 제거를…", 빨간색)를 띄우고, '열쇠 관리'의 목록 맨 위에 다른 PC가 무엇을 해야 받는지 적습니다(제거: 뺀 키 고르기, 뺀 키를 모르는 PC는 이 PC의 코드 입력; 키 추가·모든 키 새로 잠그기: 이 PC의 코드 입력; 켜기·다시 올리기·이 PC 상태로 올리기: 다음 잠금 해제, 열쇠 파일을 그 PC에만 두던 PC는 코드 입력; 비밀번호 변경·짝 맺기: 다음 잠금 해제). 모든 PC가 받았으면 '열쇠 관리'의 **모든 PC 확인 완료** 를 누르세요. 그 전까지는 변경이 끝난 것이 아닙니다. 이 알림은 이 PC의 열쇠 기록에만 있는 안내이며 암호로 보호되지 않습니다.

### 쓰는 동안

- 열쇠가 바뀌면 다른 PC는 **잠금 해제할 때** 받습니다. 관문이 필요 없는 변경(비밀번호 변경 등)은 잠금 해제의 터치 그대로 받고, 관문이 필요한 변경은 열린 직후 잃어버린 키를 고르거나 코드를 입력합니다. 다른 PC에서 바꾼 **새 비밀번호** 로 열어도 됩니다: 그 PC의 열쇠 파일로는 열리지 않으므로 "서버의 새 열쇠 파일로 열어 볼까요?"가 나오고, '예'면 같은 터치로 서버의 열쇠 파일을 받고 엽니다. 그때 받지 않았다면 '열쇠 관리'에 "서버에 새 열쇠 파일 있음"이나 "서버에 확인할 열쇠 변경 있음"이 나오고, **받기…** 로 받습니다(관문은 위와 같음). 확인을 기다리는 동안 그 PC는 올리지도 합치지도 않습니다.
- 보안 키가 없는 PC(다른 PC에서 나중에 보안 키를 켠 금고)는 잠금 해제의 터치도 [받기…]도 없으므로 '열쇠 관리'의 **서버의 새 열쇠 파일 받기…** 로 받습니다(위 '보안 키 없이 만든 금고에 나중에 켜기').
- 다른 PC에서 새로 등록한 키만 가지고 있다면, '잠금 해제'에서 Windows 보안 창을 취소하세요. 서버의 열쇠 파일에 그 키가 있으면 "…그 키로 열어 볼까요?"가 나오고, 새 키를 터치한 뒤 그 PC의 코드를 입력하면 받고 엽니다.
- 두 PC에서 동시에 열쇠를 바꾸면 "서버의 열쇠 파일과 갈라짐"이 나오고 동기화가 멈춥니다. 한 PC에서 **받기…** 로 합치세요(**다른 PC 쪽 사용** 또는 **둘 다 합치기**). 그런 일이 없었다면 서버 사본이 위조되었을 수 있습니다.
- 두 PC가 같은 상태에서 **키 제거만** 따로 한 경우(같은 잃어버린 키를 두 PC에서 각자 뺌)는 스스로 합칩니다. 서버에 늦게 올린 PC가 다음 잠금 해제 때 그 잠금 해제의 터치와 비밀번호로 다른 PC의 열쇠 파일을 열어, 묻지 않고 둘을 합친 열쇠 파일(새 데이터 키)을 씁니다. 상태 줄에 "두 PC에서 따로 한 보안 키 제거를 합쳤습니다…"가 나오고, 먼저 올린 PC는 그 결과를 다음 잠금 해제 때 확인 없이 받습니다. 한쪽에서 비밀번호도 바꿨거나 이 PC의 키가 그 열쇠 파일에서 빠졌다면 묻지 않고는 열 수 없으므로 자동으로 합치지 않고, "…[받기]로 합칠 수 있습니다"가 나오면 **받기…** 로 합칩니다(다른 비밀번호나 다른 키를 묻습니다). 그 열쇠 파일이 이 PC의 보안 키와 비밀번호로 열리지 않으면 아무것도 쓰지 않고 "위조된 연결"로 받지 않으며, 고요 금고를 다시 시작할 때까지 다시 열어 보지 않습니다.
- 이 PC의 열쇠 파일이 서버에서 거부되면 그동안 이 PC의 금고는 올라가지 않습니다(goyo-sync 상태 `keyfile`이나 `refused`). goyo-sync와 서버 스크립트를 같은 버전으로 맞추세요.
- 서버에 이 금고의 열쇠 파일이 없어지면("열쇠 파일: 서버로 동기화 (실험) · 서버에 없음") 다른 PC에서 끈 것일 수 있습니다. 그렇다면 다시 올리지 말고 그 PC의 열쇠 파일을 USB로 받으세요. 아무도 끄지 않았는데 지워진 것이 확실할 때만 **열쇠 파일 다시 올리기** 를 누르세요. 그 전까지 이 PC는 서버 사본을 합치지도 올리지도 않습니다.
- 확인을 기다리는 변경을 한 PC가 사라졌다면 **다른 PC가 없어 이 PC 상태로 올리기…** 를 쓰세요(위 '다른 PC가 받는 관문'). 그 버튼이 없는 변경(이 PC의 키를 제거하는 변경 등)은 '잃어버린 키 제거'를 하거나 열쇠 파일 동기화를 끕니다. 변경이 위조라고 확신할 때만 **받지 않기…** 로 끝냅니다.

### 열쇠 변경 자동 적용 (이 서버를 믿음)

**기본은 꺼져 있습니다.** 켜면, 다른 PC에서 한 열쇠 변경(보안 키 제거, 보안 키 추가, 비밀번호 변경 같은 것)이 서버로 왔을 때 이 PC가 **잃어버린 키를 고르라고 하거나 그 PC의 열쇠 확인 코드를 묻지 않고** 받습니다. 편해지는 대신 서버를 믿는 설정입니다. 아래 '위험'을 읽고 켜세요.

- **어디서:** '열쇠 관리'의 열쇠 파일 줄 오른쪽에 있는 **열쇠 변경 자동 적용 (이 서버를 믿음)** 스위치. 열쇠 파일을 서버로 동기화하는 금고에서만 보이고, 이 PC가 그 열쇠 파일을 이미 확인했을 때만 켤 수 있습니다(새 PC는 처음 코드를 입력한 뒤에야 켤 수 있음).
- **이 PC, 이 금고에만:** 설정은 이 PC의 열쇠 기록(`goyo-vault.keys`)에만 적힙니다. 서버나 다른 PC로 가지 않고, 열쇠 파일도 바뀌지 않습니다. 켤 때 위험 질문을 한 번 묻고(기본 '아니요'), 끌 때는 묻지 않습니다. 어느 쪽도 비밀번호는 묻지 않습니다. 이 금고의 기록을 지우면('이 금고의 기록 지우고 다시 확인…') 꺼진 상태로 돌아갑니다.
- **켜면 달라지는 것:** 받는 때는 그대로입니다. 잠금 해제할 때, '열쇠 관리'의 **받기…**, 다른 PC에서 바꾼 새 비밀번호로 열 때의 "서버의 새 열쇠 파일로 열어 볼까요?"뿐입니다. 그때 고르기·코드 질문과 미리보기 없이 받고, 상태 줄에 "열쇠 파일 변경을 적용했습니다: 보안 키 3 제거. 열쇠 확인 코드 …"처럼 무엇이 바뀌었는지 알립니다. 금고를 연 채로 있는 동안 변경이 오면 '열쇠 관리'에 "서버에 새 열쇠 파일 있음"이 보이고, 그때까지 이 PC는 올리지도 합치지도 않습니다. **잠금 해제나 [받기…] 없이 혼자 받는 일은 없습니다.**
- **그대로인 것:** 새 열쇠 파일을 열 때의 보안 키 터치와 비밀번호. 터치하기 전의 모든 위조 검사(이 PC에서 뺀 키가 만든 파일, 이 PC가 아는 제거 기록이 빠진 파일, 예전 파일, 너무 앞선 수정 번호 등은 켜져 있어도 거부). 키를 뺀 뒤 나오는 '동기화로 들어온 변경 확인'. 받을 때 꼭 필요한 다른 질문(다른 키 터치, 다른 비밀번호, 일시 정지 동의, 비밀번호만으로 여는 열쇠 파일로 바꾸기, 열쇠 파일 동기화 끄기를 따를지). 자동으로 받은 변경은 꺼진 '잃어버린 키 고르기'를 다시 켜지 않습니다(한 번 틀려 코드만 남은 금고는 이 설정을 끈 뒤에도 코드만 남습니다).
- **쓰지 않는 곳:** USB로 가져온 열쇠 파일('새 열쇠 파일 받기'), 새 PC의 처음 확인(코드 입력이나 '코드 없이 받기 (이 서버를 믿음)…'), 두 PC에서 따로 바꿔 갈라진 열쇠 파일('다른 PC 쪽 사용'·'둘 다 합치기'). 이런 경우에는 켜져 있어도 예전처럼 묻습니다. 보안 키가 없는 PC에는 이 스위치가 없습니다('서버의 새 열쇠 파일 받기…'는 늘 코드나 '코드 없이 이 서버를 믿고 받기…'를 묻습니다).
- **다른 PC는:** 이 설정은 켠 PC에만 적용됩니다. 켜지 않은 PC는 예전처럼 잃어버린 키를 고르거나 코드를 입력합니다. 열쇠를 바꾼 PC는 그대로 코드를 보여 주고 "다른 PC들이 이 열쇠 변경을 받았는지 확인 전입니다…"도 그대로 띄웁니다. 자동 적용을 켠 PC에서는 코드를 입력하지 않아도 되지만, 받은 뒤 그 PC의 열쇠 확인 코드가 바꾼 PC의 코드와 같은지 한 번 보고 **모든 PC 확인 완료** 를 누르세요.
- **위험:** 서버에 열쇠 파일을 올릴 수 있는 사람(서버를 장악했거나 어느 PC의 동기화 SSH 키를 가진 사람)이 **이 금고의 보안 키 하나와 그 PIN, 비밀번호까지** 함께 가지고 있으면, 그 사람이 만든 열쇠 변경을 이 PC가 다음 잠금 해제 때 묻지 않고 받습니다. 그러면 이 PC는 그 사람이 아는 데이터 키로 바뀌어, 그 뒤 이 PC에서 저장하는 내용을 그 사람이 읽을 수 있습니다. 꺼져 있다면 그런 변경은 고르기나 코드에서 멈춥니다. 보안 키를 잃어버렸고 PIN과 비밀번호도 새었을 수 있을 때가 가장 위험합니다: 그 사람이 서버에도 올릴 수 있다면, 다른 PC가 제거를 받기 전에 그가 먼저 만든 변경이 받아질 수 있습니다. 그럴 때는 손에 있는 PC에서 제거한 뒤 이 설정을 켠 PC마다 열쇠 확인 코드가 제거한 PC와 같은지 확인하고, 다르거나 '서버의 열쇠 파일과 갈라짐'이 나오면 그 PC에서도 **잃어버린 키 제거** 를 하세요. 서버나 동기화 SSH 키를 쥔 사람, 또는 보안 키+PIN+비밀번호를 가진 사람 가운데 한쪽만 있다면 이 설정이 켜져 있어도 받아지는 위조는 없습니다.

### 새 PC

권장: 새 PC에는 열쇠 파일을 **USB로** 처음 옮깁니다. 처음 열 때 그 열쇠 파일을 처음 보므로 다른 PC의 열쇠 확인 코드를 입력합니다.

**서버에서 시작하기**(열쇠 파일을 잃어버린 PC도 같습니다):

1. 보안 키 빌드의 goyo-sync 설정 창에서 **이 PC로 가져오기…** 를 누르고 금고와 저장할 폴더를 고릅니다. 금고 파일은 그 폴더에 `vault.goyo`로 저장되고, 서버에 이 금고의 열쇠 파일이 있으면 그 옆 동기화 폴더(`vault.goyo.sync\incoming.goyokeysync`)에만 둡니다. 열쇠 파일(`.goyokey`)은 만들지 않습니다. 그 금고는 goyo-sync의 동기화 목록에도 들어갑니다.
2. 고요 금고를 엽니다. 그 폴더가 고요 금고의 폴더라면 바로, 아니면 시작 화면의 **금고 파일 열기 (다른 폴더 · 서버에서 가져온 금고)**(또는 로그인 화면의 **찾기**)로 그 `vault.goyo`를 고르면 **서버에서 가져온 금고** 화면이 나옵니다. 무엇이 일어났는지와 남은 세 단계가 적혀 있습니다. 비밀번호를 입력하고 **다음 · 보안 키 터치** 를 누른 뒤 보안 키를 터치합니다(서버의 열쇠 파일에 보안 키가 없으면 버튼은 **다음** 이고 터치는 없습니다). 이 PC가 전에 연 금고를 열쇠 파일이 있는 곳(USB 등)과 함께 고르면 이 화면이 아니라 평소 로그인으로 열립니다.
3. 열린 금고는 아직 읽기 전용입니다. 오른쪽 **서버에서 가져온 열쇠 파일 확인** 칸에 다른 PC의 '열쇠 관리'에 지금 보이는 열쇠 확인 코드(`E7 · 1A2B-3C4D-5E6F-7A8B` 꼴)를 입력하고 **코드 확인** 을 누릅니다. 그 전에는 항목을 고칠 수 없고, 열쇠 파일과 금고 파일을 이 PC에 저장하지도 않습니다. 코드가 틀리면 창으로 알려 주고, 입력한 코드는 칸에 그대로 남아 고쳐 쓸 수 있습니다. 이 단계가 끝나기 전에는 아래 **금고 백업**, **열쇠 백업**, **열쇠 관리** 가 흐리게 꺼져 있습니다. 확인할 다른 PC가 없으면 **코드 없이 받기 (이 서버를 믿음)…** 가 위험 경고를 보인 뒤 저장 단계로 넘어가며, 그때 저장 창은 "코드 없이 이 서버를 믿기로 했습니다"라고 말합니다(진짜인지 확인했다고 하지 않습니다).
4. 코드가 맞으면 "열쇠 파일을 금고 옆에 저장합니다"가 나옵니다. **여기에 저장** 이면 금고 옆에 `vault.goyokey`로, **다른 곳에 저장…** 이면 고른 곳(동기화 폴더 밖, 이미 있는 파일 위에는 쓰지 않음)에 저장합니다. 그다음 열쇠 파일, 그 자리의 금고 파일, 이 PC의 열쇠 기록을 차례로 씁니다. 다음부터는 평소처럼 열립니다. 이 PC의 서버 동기화도 이때 바로 시작됩니다. 그 사이에 끊기면:
   - 열쇠 파일이 이미 있으면 로그인 화면에서 평소처럼 여세요. 열면 이 PC의 열쇠 기록이 마저 끝납니다.
   - 그렇지 않으면 고요 금고를 다시 열면 같은 화면이 나옵니다. 코드를 다시 묻지 않고 **저장하기** 만 남습니다. 열쇠 파일은 **처음과 같은 이름** 으로 저장하세요. 그 이름에 끊기기 전에 쓴 열쇠 파일이 그대로 있으면 그 파일을 씁니다(내용이 조금이라도 다르면 덮어쓰지 않고 다른 이름을 고르라고 합니다).
5. 이 PC에 금고 파일이 있다면(열쇠 파일만 잃어버린 경우) 그 금고 파일이 기준입니다. 서버의 열쇠 파일이 그 금고 파일보다 오래되었으면 열지 않습니다. 이 PC가 기록해 둔 열쇠와 맞지 않는 열쇠 파일(갈라진 것, 예전 것)도 열지 않습니다.

서버에 이 금고의 열쇠 파일이 없으면(열쇠 파일을 PC에만 두는 금고) 같은 폴더에 다른 PC의 열쇠 파일을 USB로 `vault.goyokey` 이름으로 넣고 평소처럼 엽니다. 처음 보는 열쇠 파일이므로 같은 코드 칸이 나옵니다. **백업 파일로 되살리기** 는 '금고 백업'으로 만든 백업 파일 전용입니다. 그 화면에서 서버에서 가져온 금고 파일을 고르면(이 PC에 그 열쇠 파일이 없을 때) "이 파일은 서버에서 가져온 금고입니다"와 **서버에서 가져온 금고로 열기** 버튼이 나오고, 누르면 위의 **서버에서 가져온 금고** 화면으로 넘어갑니다.

다른 PC가 없으면 믿고 쓸 수밖에 없습니다(위 '코드 없이 받기 (이 서버를 믿음)…'). 저장한 뒤 **열쇠 백업** 을 하세요.

### 끄기

'열쇠 관리' › **열쇠 파일 동기화 끄기…**(**보안 키 끄기** 를 해도 열쇠 파일 동기화가 함께 꺼집니다):

1. 이 PC가 서버에 열쇠 파일 삭제를 요청하고 데이터 키를 바꿔, 올릴 수 없는 열쇠 파일(열쇠 파일 동기화 끄기는 `GOYOKH01`, 보안 키 끄기는 `GOYOKE03`)을 씁니다. 그 뒤 이 PC는 열쇠 파일을 올리지 않습니다.
2. 삭제는 보안 키 빌드의 goyo-sync가 실행될 때 서버로 갑니다. '열쇠 관리'에 "서버의 열쇠 파일 삭제: 대기 중"이 보이다가, 서버가 답하면 "서버가 삭제했다고 응답함 (기록 N)"이 한 번 나옵니다. '완료'라고는 하지 않습니다: 해킹된 서버는 지우지 않았을 수 있습니다.
3. 끄기는 서버에 있는 이 금고의 **현재 열쇠 파일 기록 전체** 를 끝냅니다. 이 PC가 아직 받지 않은 다른 PC의 변경(예: 비밀번호 변경)이 그 사이 올라왔다면 그것도 서버에서 지워지니, 그 PC와는 USB로 한 번씩 열쇠 파일을 주고받으세요. 끄기 전에 "서버에 이 PC가 받지 않은 열쇠 파일(수정 N)이 있습니다…"가 나오면 그 뜻입니다.
4. 다른 PC는 동기화를 멈추고 이 열쇠 파일을 USB로 받아야 합니다('새 열쇠 파일 받기', 코드 입력). 다른 PC에서 다시 서버로 올려 되돌리지 마세요. 그 PC도 끌지는 USB로 받으면서 정하세요.
5. 다시 켜지 않을 거라면, 모든 PC가 받은 뒤 모든 PC의 강제 명령에서 이 금고 ID를 `--key-sync` 목록에서 빼세요.
6. 새 열쇠 파일을 쓰기 전에 끊기면(전원 등) 다음 잠금 해제가 끄기를 되돌립니다(바뀐 것 없음, 서버 삭제 요청도 가지 않음). 다시 끄세요. 새 열쇠 파일을 쓴 뒤에 끊겼다면 다음 잠금 해제가 끄기를 마저 끝냅니다.

### PC를 잃었을 때

그 PC의 `authorized_keys` 줄을 **바로** 지우세요. 그 PC의 동기화 키로는 열쇠 파일을 받을 수 있고, 업로드를 막거나 열쇠 파일 기록을 끝낼 수 있습니다(동기화가 멈출 뿐, 위조된 열쇠 파일이 받아들여지지는 않습니다). 그 키로 기록이 망가졌으면 관리자가 `data/<금고 ID>/k/`를 지워야 할 수 있습니다(그 금고를 동기화하는 PC가 없을 때). 그 PC에 등록된 보안 키도 함께 잃었다면 위 '키를 잃어버렸을 때'를 하세요.

### 동결의 한계

서버가 어떤 PC에 열쇠 변경을 계속 숨기면(동결), 그 PC는 사용자가 그곳에서 무언가 할 때까지 예전 상태로 남습니다. 그동안 잃어버린 키와 PIN, 비밀번호를 가진 사람은 그 PC가 새로 저장하는 내용을 읽고, 서버를 통해 항목을 바꿔 넣을 수 있습니다. 그가 만든 키 구성 변경은 관문에서 멈춥니다(그 PC에서 '열쇠 변경 자동 적용'을 켰다면 멈추지 않습니다). 끝내는 방법은 그 PC에서 **잃어버린 키 제거** 를 하는 것입니다.

**알아보는 방법.** 제거할 때 비밀번호를 바꿨다면 다른 PC를 **새 비밀번호** 로 여세요. 서버가 변경을 숨기고 있으면 새 비밀번호로는 열리지 않고 "서버의 새 열쇠 파일로 열어 볼까요?"도 나오지 않습니다. 그러면 예전 비밀번호로 연 뒤 **잃어버린 키 제거** 를 하세요. 비밀번호를 바꾸지 않았다면, 제거한 뒤 다른 PC를 열고 동기화가 한 번 돌 시간을 기다렸을 때 아래 알림이 하나도 나오지 않으면 서버가 변경을 숨기고 있을 수 있습니다. 그때도 그 PC에서 **잃어버린 키 제거** 를 하세요.

- 열쇠 파일 동기화를 켠 금고: "다른 PC에서 보안 키 구성이나 설정을 바꾼 열쇠 파일이 서버에 있습니다…" 또는 '열쇠 관리'의 "서버에 확인할 열쇠 변경 있음".
- 열쇠 파일이 PC에만 있는 금고: "다른 PC에서 이 금고의 열쇠를 바꿔 동기화를 멈췄습니다…".

## 남은 위험

- **일부만 실제 키로 검증했습니다.** 키 응답이 터치마다, USB와 NFC에서 같은지, credProtect 3과 두 salt 값, 두 키 허용 목록은 YubiKey 5C NFC로 확인했습니다. 재부팅·PIN 변경·수개월 뒤에도 같은지, PIN 없는 조회가 실제로 막히는지, 휴대폰·Windows Hello 거부 등은 아래 점검표의 '실행하지 않음' 항목이 통과해야 확인됩니다.
- **몰래 얻은 키 응답은 오래 갑니다.** PIN과 함께 키를 잠깐 손에 넣어 터치한 사람은 그 키가 빠지거나 '모든 키 새로 잠그기'를 할 때까지 그 키를 복제한 것과 같습니다. 그런 복제는 '잃어버린 키 고르기' 관문도 통과할 수 있고, 코드 입력만 막습니다. 키마다 다른 PIN을 쓰세요.
- **동결**(위). 어떤 설계로도 피할 수 없습니다.
- **새 PC나 재해 복구에서 확인할 다른 PC가 없으면** 믿고 쓸 수밖에 없습니다. 보안 키가 없는 PC가 **코드 없이 이 서버를 믿고 받기…** 로 받은 열쇠 파일도 같습니다: 서버를 장악하고 비밀번호를 아는 사람이 자기 보안 키로 만든 파일일 수 있고, 그렇다면 그 사람은 그 뒤 그 PC에서 저장하는 내용을 읽을 수 있습니다. 코드를 볼 수 있으면 코드로 받으세요.
- **열쇠 변경 자동 적용을 켠 PC**는 서버에 올릴 수 있는 사람이 보안 키 하나와 그 PIN, 비밀번호까지 가지면 그 사람이 만든 열쇠 변경을 묻지 않고 받습니다(위 '열쇠 변경 자동 적용'). 기본은 꺼져 있습니다.
- **예전 기록.** 키가 빠지기 전에 저장한 모든 것은 그 키와 PIN, 비밀번호, 예전 열쇠 파일을 가진 사람이 읽을 수 있습니다. 열쇠 파일 동기화를 켰다면 서버의 예전 열쇠 파일이 그 사본입니다.
- **사용자 실수.** 잃어버린 키보다 적게 고르면 두 키를 가진 사람이 함께 만든 변경이 통과할 수 있습니다. 다른 화면의 코드를 잘못 입력해도 그렇습니다. 잃어버린 키는 **모두** 고르세요.
- **예비 키의 짝 맺기 방문 전.** 그 키는 만나지 못한 키를 대신할 수 없고, 그 사이 두 번째 분실이 오면 홀로 남을 수 있습니다.
- **알아채기 전.** 분실을 알아채기 전에는 그 키를 가진 사람(PIN과 비밀번호까지)이 정식 사용자와 같습니다. 검토 목록은 날짜가 실제와 가까울 때만 도움이 됩니다.
- **서비스 거부와 알림 피로.** 서버는 동기화를 멈추게 하거나, 갈라지게 하거나, 변경을 관문에 세워 둘 수 있습니다. 데이터는 잃지 않습니다.
- **이 PC의 기록은 인증되지 않습니다.** 같은 사용자 권한의 코드는 바꾸거나 지울 수 있습니다.
- **동기화 폴더의 요청 파일도 인증되지 않습니다.** 그 폴더에 쓸 수 있는 사람(공유 폴더, NAS)은 그 PC의 도우미가 서버의 열쇠 파일 기록을 끝내거나 예전 금고 기록을 지우게 할 수 있습니다(동기화 방해, 위조 열쇠 파일은 아님).
- **서버에 보이는 정보.** 모든 방식에서: 금고 파일 머리글(키 ID, 수정 번호, 상태 태그, 보안 키와 열쇠 파일 동기화를 쓰는지). 그러니 열쇠를 몇 번 바꿨는지와 대략 언제인지. 열쇠 파일 동기화를 켜면 그에 더해 열쇠 파일 전체: 변경 종류, 승인한 키 번호, 키·제거 기록·짝 기록 수, 등록 시각, 자격 증명 ID, 변경 시각, 보고한 분실 날짜.
- **Windows.** PIN 창은 화면 캡처 차단 밖이고, PIN과 키 응답은 Windows를 거치며 그 버퍼는 지울 수 없습니다.

자세한 위협 분석은 [SECURITY_REVIEW.md](SECURITY_REVIEW.md)의 '0.9.0 변경: 보안 키(실험)와 열쇠 파일 동기화(실험)', 파일 형식은 [FORMAT.md](FORMAT.md)에 있습니다.

## 기본 빌드가 보안 키 열쇠 파일을 만나면

릴리스 ZIP의 `goyo-vault.exe`는 보안 키로 잠긴 열쇠 파일(첫 8바이트가 `GOYOKH`나 `GOYOKS`로 시작하는 파일)을 열지 않습니다. 파일을 고르는 순간에, 그리고 '열기'나 '복원'을 누르면 비밀번호를 확인하기 전에 첫 8바이트만 보고 "이 열쇠 파일은 보안 키(YubiKey 등)가 있어야 열립니다…"라고 알립니다. 비밀번호가 틀렸다고 하지 않고, 실패로 세지 않으며, 다시 시도 대기 시간도 없습니다. 파일이 잘렸거나 더 새로운 버전에서 만들어 형식 검사를 통과하지 못하면 "파일이 손상되었거나 더 새로운 버전에서 만든 파일일 수도 있습니다."를 덧붙입니다. 기본 빌드는 그런 파일이 손상된 것인지 판단할 수 없으므로, 저장이 끊기며 남은 임시 파일(`.goyotmp`)로 바꿔 넣지도 않습니다. 보안 키 열쇠 파일로 저장된 금고 파일을 그 열쇠가 없는 열쇠 파일로 열면 "이 금고 파일은 보안 키로 잠긴 열쇠 파일로 저장되었습니다…"라고 알리고 열지 않습니다. 이런 파일을 열려면 보안 키 기능이 든 빌드가 필요합니다.

받은 열쇠 파일이 "설명되지 않는 변경"으로 거부되었다면(다른 PC에서 비밀번호를 이 PC가 아직 쓰는 비밀번호로 되돌린 경우), 이 PC에서 먼저 비밀번호를 바꾸세요. 그러면 그 파일은 갈라진 파일이 되어 '새 열쇠 파일 받기'가 두 파일을 합칩니다.

## 실제 보안 키 점검표

보안 키 기능이 기본으로 켜지거나 열쇠 파일 동기화가 '실험'을 벗어나려면 아래가 모두 실제 키로 통과해야 합니다. 하나라도 실패하면 기능은 기본으로 꺼진 채 남습니다. PIN 강제, USB/NFC 전용, 키 응답 그대로 받기를 Windows가 지킬 수 없으면 열쇠 파일 동기화는 아예 제공하지 않습니다.

**결과: 일부 실행.** 아래 '통과'는 모두 **YubiKey 5C NFC, Windows 11 26200, API 9** 에서 확인했습니다(키 6개, NFC 리더 HID OMNIKEY 5022). 나머지는 실행하지 않았습니다. 이 점검으로 바뀐 것: 보안 키는 늘 PIN을 씁니다(위 PIN), 모든 Windows 호출은 고요 금고 창을 소유 창으로 줍니다(소유 창 0은 0x80090027로 바로 실패), NFC로 쓸 키는 창이 열리기 전에 USB에서 뽑습니다.
